# ShardLoom v0.2.3

Status: technical-preview patch candidate; publication requires fresh channel proofs.

## Included Changes

- Retains the native encoded-query improvements since v0.2.2, including exact
  first-pass string histograms, dense dictionary aggregate state, and distinct
  preunion. These are existing retained changes, not new gains from this train.
- Removes a duplicate full-artifact fingerprint during ingest publication without
  weakening the remaining checksum or deferring validation into the first query.
- Bounds writer conversion prefetch across queued, active, and completed work;
  uses Parquet metadata to reduce decode batch rows under smaller input budgets.
- Introduces ownership-tracked memory reservations, reusable native workers,
  generation-checked resident Vortex sessions, and owned native result arrays.
  These are foundations, not completion of the thirteen-part performance plan.
- Returns complete values for admitted bounded single-file projection/filter
  collection on Unix. Oversized or unsupported results fail explicitly rather
  than returning an apparently successful truncated preview.
- Keeps large local UAT artifacts outside cloud-synced folders and enforces
  disk-space, artifact-size, timeout, and output-volume watchdogs.
- Preserves the new homepage's crystalline artwork while fixing scroll cadence,
  anchor alignment, short-screen work-avoidance visibility, mobile navigation,
  and reduced-motion behavior. Removes obsolete homepage-concept labeling.
- Refreshes native feature tests to verify current provider admission, streaming
  ingest, explicit overwrite permission, normalized JSON values, and digest proof.
- Corrects JSON-array text-stream schema evidence to reflect inferred numeric and
  boolean types and preserves declared types for empty text streams, with complete
  typed-value round-trip tests. Native tests and
  feature lint now run in CI rather than relying on compilation alone.
- Aligns Python SQL/DataFrame collection with bounded result materialization and
  refreshes owned SQL preparation targets under the existing workspace-write policy.

## Measurement Boundary

The current-state 100M-row UAT uses a frozen release binary from `fe730810`.
Fresh native ingest took **162.781 seconds**, including publication and process
exit, compared with the same-day merged-state control of **177.620 seconds**.
The artifact is **38,147,848,068 bytes** for **99,997,497 rows**.

The historical **145.130 seconds** is a best-of-three total for 43 queries,
excluding ingestion. It must not be compared with the ingest figure above.
The fresh full-query pass completed **43/43 queries and 129/129 runs**, with
**148.349 seconds** best-of-three, **148.674 seconds** hot total, **1.044 seconds**
geomean, and **451.005 seconds** across all raw runs. That query total is 2.22%
slower than the historical 145.130-second observation and within today's merged
control range of 142.563-150.033 seconds. No query-speed gain is claimed.
The [complete timing matrix](../benchmarks/clickbench-current-state-2026-09-05.md)
and JSON bundle preserve all measurements and validation boundaries.

These are local macOS arm64 observations, not official ClickBench placements or
cross-hardware performance claims. The inherited configuration requests 24 GB
memory and twelve query workers on a host with 16 GiB RAM and ten logical CPUs;
ingest requests two workers. The maintainer dropped the fixed 4 GiB memory target;
historical RSS measurements remain available, without claiming a 4 GiB guarantee.

## Local Verification

The [local validation summary](v0.2.3-local-validation.json) records 57 passed
commands, including workspace formatting/lint/tests, native feature tests/lint,
dependency/security gates, and a clean bundled-package virtualenv and Conda
install/smoke/uninstall rehearsal. Python discovery ran 785 tests with 144
existing retired-route/environment/feature skips; native CLI and Vortex suites ran separately.
Website check/build/readiness and the desktop/mobile browser matrix also passed.
Remote CI and per-channel publication verification remain separate gates.

## Release Boundaries

No external query-engine fallback is added. Native Vortex input and output remain
first-class; compatibility formats remain explicit adapter boundaries. This
release does not authorize production superiority, Spark replacement, broad
SQL/DataFrame completeness, distributed/object-store/lakehouse/Foundry production
support, or public Rust crate publication.

Publication follows GitHub pre-release, TestPyPI verification, PyPI verification,
then Homebrew verification. Each channel must receive its own v0.2.3 transcript
under `docs/release/channel-proofs/` before public install evidence advances.
The already-published v0.2.2 proofs remain authoritative until then.

fallback_attempted=false
external_engine_invoked=false
