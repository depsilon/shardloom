# ShardLoom v1.0.0

Status: release preparation authorized October 25, 2026. Selected-channel
publication and installation proof are pending. The
[publication record](v1.0.0-publication-verification.md) will identify the exact
release source and artifacts. The current published package remains v0.7.0
until the new channel proofs pass.

ShardLoom is a unified data processing engine. SQL, Python DataFrames and the
CLI describe work for the same engine, with explicit readers and writers for
supported formats. This release packages the accepted runtime through
[PR #1605](https://github.com/depsilon/shardloom/pull/1605), including corrected
query semantics, shared execution across interfaces, the Vortex provider
refresh and reduced ingestion copying.

## Changes since v0.7.0

- Large-integer averages and regex-domain grouping now agree with the frozen
  independent reference. The
  [correctness acceptance](../benchmarks/native-independent-full43-2026-10-22.md)
  retains every original failure and the complete corrected 381-row result.
- Accepted [native operator optimizations](../architecture/native-engine-optimization-acceptance-2026-10-23.md)
  and [grouped preparation](../architecture/native-grouped-preparation-2026-10-24.md)
  reduce measured work in their admitted families. Their finite comparisons
  and controls govern the claims; they do not establish a universal speedup.
- The [interface parity correction](../architecture/native-user-surface-execution-parity-2026-10-24.md)
  brings equivalent CLI, workflow, Python SQL, DataFrame and typed plans into
  the shared provider selection. Aliases, metadata-only counts, pure
  projections and repeated reductions preserve the admitted native path.
  Correctness acceptance and the remaining failed timing controls are recorded
  separately.
- The [provider refresh](../benchmarks/native-vortex-provider-refresh-2026-10-24.md)
  updates the coherent Vortex 0.90 / Arrow 59.3.1 graph. Native provider APIs
  remain isolated and policy-admitted. Query-engine integrations are not used
  to execute unsupported work.
- The [ingestion ownership change](../architecture/native-ingest-ownership-preparation-2026-10-24.md)
  removes 61.2% of the measured copied bytes while producing an independently
  verified byte-identical Vortex file. It was retained for copy reduction;
  its frozen 3% ingest-speed gate did not pass.
- [Public naming and reports](../architecture/shardloom-public-naming-2026-10-24.md)
  consistently describe one engine and distinguish planned work, preparation,
  execution and completed output. The [dependency intake](../architecture/dependency-intake-2026-10-25.md)
  and [CI revision](ci-performance-2026-10-25.md) keep release checks aligned with
  the current provider and package graph.

## Migration and compatibility

The version change itself adds no runtime behavior or machine-schema changes.
Applications using the documented v0.7.0 Context/Result, SQL, DataFrame and CLI
interfaces can keep their existing calls. Human-readable descriptions and
reports have changed; automated consumers should use the structured output.
The [Python migration reference](../reference/python-api-migration.md) continues
to describe context ownership, explicit resources, transport selection, typed
errors and result lifetimes.

The existing [v1 schema contract](v1-api-schema-stability-matrix.json) governs
its enumerated machine-readable fields and compatibility aliases. Field
removal, semantic renaming or type narrowing requires migration notes,
compatibility tests and explicit breaking-change approval. Internal Rust
crates remain unpublished. Experimental, diagnostic and unsupported surfaces
retain their documented status; the package number does not promote them to
stable APIs or close the independent capability gates.

Linux and macOS use the native Python package; Windows retains the CLI-backed
package. Actual wheel filenames and installed-package proofs determine OS,
architecture and interpreter coverage. Python requires 3.10 or newer; platform
and ABI restrictions still apply. No backend is silently substituted when a
selected execution path is unsupported or fails.

## Evidence and release scope

The [workflow experiment](../benchmarks/native-workflow-drop-2026-10-25.md)
failed its combined regression gate and was removed in full. Earlier focused
mechanism passes do not make any part of that dropped runtime release content.
The subsequent [ingestion investigation](../benchmarks/native-ingest-window-decision-2026-10-25.md)
closed without another runtime change when the maintainer advanced this train.
Unmeasured scheduling ideas and rejected PGO, region, warm-cache and encoding
candidates remain outside the release.

The restored current-main runtime completed one isolated Full43 pass at
**47.889862794 engine seconds**, with one execution of each of 43 queries and
all 381 result rows checked. That pre-bump observation retains its original
source, binary, input and reference identities. It is not a measurement of the
v1.0.0 packages, a paired speedup claim or a reason to rerun the workload for a
version-only change.

Publication follows GitHub pre-release assets, TestPyPI, PyPI and Homebrew,
each with separate source/artifact identity and install, smoke and uninstall
proof. Checksum manifests and dependency inventories accompany the artifacts;
they are not signed attestations or complete linked-library inventories.
The release retains technical-preview support boundaries and does not claim
production readiness, general SQL/DataFrame parity, Foundry support, broader
remote/lakehouse support or superiority to another engine. Vortex remains
native input/output, and unsupported execution fails explicitly without an
external engine fallback.
