# ShardLoom v1.0.0 publication verification

Status: GitHub prerelease, TestPyPI, PyPI and Homebrew publication and
installation proofs pass. Documentation integration and public-site
verification remain pending.

## Release source

The release source is `99d62ae3d10117720206463a27527a936623d182`, tree
`7ab32e35c056dfbb76cc711a747ea4864c6feba1`, from
[PR #1606](https://github.com/depsilon/shardloom/pull/1606). All 56 checks on
the exact PR revision passed. The merged source passed 53 repository checks
and one Workers check (54 total), including exact-source CI run
[40234450198](https://github.com/depsilon/shardloom/actions/runs/40234450198).
The accepted PR and merged source have identical trees. Primary review found no
blocking findings; the hosted review completed without findings and is not
described as a formal approval.

The [source and package acceptance record](evidence/v1.0.0-source-package-acceptance-2026-10-25.json)
verifies 2,858 frozen source identities, exported-source build verification,
local installed-package checks and hosted native-wheel results. Its pending
channel fields describe the pre-publication observation; later channel proofs
establish publication separately.

The source acceptance includes local and hosted native suites of 140 tests,
with no failures, errors or skips, across 13 source modules; Linux native
payload inspection retained 280 payload files. These bounded package and
platform proofs do not imply universal OS, ABI, interpreter or workload
coverage. Windows remains CLI-backed support evidence; it is not native Python
extension parity. Python requires 3.10 or newer. The release remains an
unsigned lightweight tag and a technical preview.

The pre-bump Full43 observation completed one execution of each of 43 queries
at **47.889862794 engine seconds**. It retains its original source and input
identities from before the version bump; it is not a measurement of the v1.0.0
package and establishes no speedup claim.

## Artifact identity and scope

Independent observation matched all eight published distributions to their
registry digests and original build artifacts. Twelve workflow archives include
the distributions and four original installed-native-wheel proof packets. The
Linux x86_64 and macOS arm64 proofs from each registry contain all 140 named
tests from the 13 release-source modules, with no failures, errors or skips;
their original commands, logs and uninstall results were checked. The source
comparison preserved all 2,858 frozen source identities. Forty-three verifier
tests passed, including rejection of changed results, incorrect counts and
unbound artifact identities.

The [TestPyPI provenance](channel-proofs/testpypi-v1.0.0-provenance.json) and
[PyPI provenance](channel-proofs/pypi-v1.0.0-provenance.json) retain the actual
build identities and complete artifact inventories, linked checksums and
dependency inventories. Linux uses `manylinux_2_39_x86_64`; macOS uses
`macosx_26_0_arm64`, both with the CPython 3.10 stable ABI. The Windows wheel
is specific to CPython 3.13 on x86_64 and contains the CLI-backed package.

The GitHub source archive SHA-256 is
`44186aa613456082dbc99223099d0732611397c165088d7c1e99a2655bc3acdb`.
The lightweight tag points to the GitHub-verified release merge. The tag and
assets are unsigned. Dependency and artifact inventories are not signed build
attestations or complete linked-library inventories.

Immutable package descriptions captured the README before public-channel
selection advanced. The inspected GitHub, TestPyPI and PyPI wheel metadata
versions are 1.0.0, but their embedded release blocks still name 0.7.0. Published
artifacts remain unchanged; this
wording limitation does not alter their identities or tested behavior. The
[current package guide](../getting-started/package-user-install.md) and release
notes carry the maintained installation guidance.

The CLI-backed Windows package does not establish native Python module or
pressure/runtime parity. No platform proof here establishes support beyond
the named artifact lanes. ShardLoom remains a technical preview, not a claim
of production readiness, broad SQL/DataFrame parity, Foundry support, general
remote/lakehouse support or superiority to another engine. Vortex remains
native input and the highest-fidelity output. Unsupported execution fails
explicitly; there is no Spark or DataFusion fallback.
