# ShardLoom v0.3.3

Status: source preparation for a technical-preview release. Publication requires
new GitHub, TestPyPI, PyPI and Homebrew proofs in that order. The selected
published-channel contract remains v0.3.2 until those proofs are complete.

This patch reduces string-aggregation work in the shared Vortex-native runtime
and closes native reader lifetime and metadata-only admission gaps. SQL, Python,
DataFrame and CLI surfaces reuse those execution families without external
query-engine fallback.

## Included changes

- Input-backed string dictionaries and borrowed count lookup avoid copying
  dictionary text merely to inspect or count it. Escaping aggregate state retains
  an explicit owner; exact equality and null semantics remain unchanged.
- Certified complete-count partitions restrict eligible exact DISTINCT work to
  winning groups. Mixed-measure workers share existing chunk partials and bounded
  owned completion, while ineligible plans keep their existing native route.
- Compact string-count pages share the same consumer across serial and worker
  execution, reducing state and merge work for admitted single-string counts.
- Bounded dictionary preparation overlaps with existing native provider progress
  for admitted URL-domain grouping. Ordered consumption, capacity admission,
  cancellation and prepared-session reuse remain explicit.
- Operation completion drains native readers and cancelled I/O. Footer-only and
  fully pruned work defers payload-owner admission and avoids unnecessary worker
  startup, including prepared calls with no spare memory credit.
- README, website and runtime guide describe the implemented ownership,
  preparation, aggregation and output contracts. Compatibility URLs lead to
  current pages, and executable examples use the current public result envelope.

## Validation and timing

The final pre-release runtime source `93ee6b39` passed formatting, workspace
Clippy, 3,436 workspace tests, 2,042 native tests and 1,520 release-feature CLI
tests. The native suite retains 22 existing ignored cases. Counts overlap across
feature configurations. The paired Full43 run passed all 258 complete-result
comparisons; a separate Q35 follow-up passed six more. Independent evidence
reconstruction checked source, binary, timing, full outputs and archive identities.

In that final dictionary-preparation comparison, Q29's best of three complete CLI
calls fell from 6.862137s to 4.825826s (29.67%). The sum of all 43 queries' best
calls fell from 54.660584s to 53.171336s (2.72%). Q35 was slower: 13.75% in that
cohort and 4.36% in a separate reversed-order follow-up. The follow-up does not
replace any sample in the Full43 total. These are workload-specific development
measurements against the immediately preceding optimization build, not a measured
0.3.2-to-0.3.3 package comparison or a production claim. See the
[final profile](../architecture/performance-profile-refresh-2026-09-30.md) and
[dictionary preparation record](../architecture/dictionary-preparation-screen-2026-09-30.md).

The source preparation also consolidates compatible dependency updates. It
therefore requires fresh broad source, native-feature, package and schema/export
checks, followed by exact-source CI and separate installation proof for each
published channel. Earlier runtime measurements are not relabelled as measurements
of those updated dependencies.

## Compatibility and boundaries

CLI, Python, website package metadata and the internal Rust workspace advance
together to 0.3.3. Internal Rust crates remain unpublished. Machine-readable
schema versions and public operator admission do not change. The dependency
intake advances bytes, serde and the pinned CodeQL action; Vortex and the
Arrow/Parquet/ORC graph stay at the previously admitted versions. See the
[intake decisions](v0.3.3-dependency-intake.md).

The existing output bounds, format-specific limitations, spill support and
deterministic unsupported diagnostics remain in force. These changes do not
establish every-operator/every-sink parity, broad spill recovery or production
serving fairness. Native Vortex preparation still preserves the input layout;
this patch does not make every I/O path produce the same optimized layout.
The interrupted format pulse and large text-format performance tests stay paused.

Package access remains a technical preview, without production-readiness,
competitive-superiority, broad SQL/DataFrame, object-store, lakehouse or Foundry
claims. After all release channels and the deployed site pass verification, the
authorized ship/drop campaign resumes from a new finite candidate packet using
the refreshed profile.
