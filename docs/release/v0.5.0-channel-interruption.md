## Failure and repair boundary

[Registry workflow 37950242761](https://github.com/depsilon/shardloom/actions/runs/37950242761)
ran once from the original release source. Linux and macOS native package builds
passed. The Windows build failed with Rust `E0433` at
`exact_distinct_spill_accumulator.rs:97`: `native_spill_session` was unavailable
because its module declaration also required `unix`. No registry publication
step ran after that failure.

The helper creates an independent Vortex session memory configuration through
portable APIs. The corrected candidate removes only its accidental Unix module
restriction while retaining its existing feature gates. Query-run-store
admission still rejects non-Unix spill before filesystem creation, and Unix-only
runtime modules keep their admission boundaries. The existing Unix permission
setting and runtime behavior are preserved. Platform-specific imports and
builder mutability are also scoped to avoid the two Windows build warnings.

The Python compatibility CI lane now builds the actual Windows native CLI using
the release feature set and invokes its version command. A regression check
rejects a lane that omits either command. This closes the missing pre-tag build
check; it does not certify Unix-only pressure/streaming behavior on Windows.

## Corrected release acceptance

The v0.5.1 candidate must pass the required Rust and Python source checks,
focused native session/run-store checks, hosted CI including the Windows native
build, and its own GitHub, TestPyPI, PyPI and Homebrew installation proofs in
that order. These checks remain pending until their actual receipts are recorded.
The [v0.5.1 release notes](v0.5.1-release-notes.md) retain the same substantial
capability milestone and its support limits.

The [fresh pre-bump UAT](../benchmarks/release-candidate-fresh-uat-2026-10-09.md)
already completed before the original bump. Its source, executable, full ingest,
129 complete query comparisons and 18 modular cohorts retain their original
identities. They are not relabeled as measurements of v0.5.1 packages. No new
speedup or platform-runtime claim follows from this build correction.
