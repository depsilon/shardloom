# ShardLoom v0.5.1

Status: corrected release candidate for the approved October 9 capability
milestone. The v0.5.0 GitHub prerelease remains immutable; its Windows native
build failed before registry upload. This candidate fixes that build boundary
and requires fresh source, Windows-build and four-channel installation evidence.
TestPyPI, PyPI and Homebrew still serve v0.4.0. See the
[channel interruption record](v0.5.0-channel-interruption.md). The full fresh UAT
completed before the original bump and retains its original source/binary identity.

ShardLoom 0.5.1 carries explicit native spill for general aggregation, joins,
analytic windows and relational pivots, alongside finite streamed input and
incremental result consumption. It also adds scalar-value subqueries, nested
pivot roles and further native allocation ownership. SQL, Python, DataFrame
declarations and the CLI continue to use the shared Vortex-native engine.
Unsupported execution fails explicitly without an external query-engine fallback.

## Windows package-build correction

The shared native spill-session helper configures memory and inherits Vortex
registries through portable APIs. Its module was incorrectly restricted to Unix
while an admitted non-Unix build referenced it. The corrected feature gate makes
that helper available without changing the separate Unix admission for spill I/O.
Two platform-specific unused-variable/import warnings are also corrected.

CI now compiles the Windows native CLI with `release-user-surfaces` and runs its
version command before a release is tagged. Python-only wheel checks did not
exercise that native build. This correction does not broaden the supported
pressure or streaming runtime envelope, change the upstream provider graph, or
establish platform parity. The feature-gated helper and run-store tests remain
part of source acceptance; actual Windows build evidence is separately required.

## Complete workloads under constrained resources

The existing optional `spill` policy declares a local workspace, disk quota and
buffer threshold. This release extends the operations that can honor that policy:

- General grouped aggregation and exact COUNT DISTINCT preserve existing
  reducers, first-seen group order, exact keys and source-order floating updates.
- All seven admitted join kinds preserve typed/nested key identity, condition
  evaluation, output ordering and unmatched rows.
- Existing ranking/navigation functions and analytic aggregates support native
  spill across admitted ROWS, GROUPS and RANGE frames and exclusions. Exact
  window DISTINCT and extrema use bounded native intermediate state.
- Relational pivots over file or resident-memory input spill growing sparse
  index/domain/cell state while preserving current values, margins, fill,
  representatives, schema binding and update order.

Resident execution remains the default. Spill is explicit; an unsupported shape,
oversized individual value, exhausted grant or disk quota still fails. Output
publication requires complete input validation, sink completion and owned cleanup.
Failure and real-process termination fixtures establish cleanup followed by a
fresh restart, not resumption of an interrupted query. See the
[spill contract and examples](../reference/native-query-spill.md).

## Batch input and result delivery

`shardloom.from_batches(...)` and `ShardLoomContext.from_batches(...)` accept
explicitly typed resident input. `iter_batches(...)` delivers admitted native
results incrementally, with final execution evidence available after complete
exhaustion. Use its context manager when stopping early; previously delivered
batches remain provisional until the final report succeeds.

Opt-in `streaming=True` retains at most one native input batch. One finite source
used once can compose with ordinary file/resident sources through admitted
scan/filter/project, sorting, aggregation, joins, analytic windows and draining
limits. A batch source can occur on either join side. Sorts and analytic windows
complete their input before producing their final relation; limits drain and
validate the whole source, including `LIMIT 0`.

The current intake contract admits nullable Int64, finite Float64, Boolean and
UTF8 fields: at most 128 fields, 2,048 rows and an 8-MiB control frame per batch,
32 MiB of typed logical bytes per batch, and 4,096 batches per source. A separate
16-MiB wire-frame ceiling includes framing and metadata. Ordinary file inputs do
not inherit these transport bounds. The resident mode still requires total
retained native input to fit the grant. Prepare compatibility files explicitly
to Vortex before incremental
consumption. See the [batch contract](../architecture/native-bounded-adapters-2026-10-06.md)
and [working examples](../getting-started/examples.md).

Repeated batch-source use, multiple producers, set operations and dynamic pivot
input remain outside streamed-input admission. Compatibility streaming
destinations, fanout, cancellation-safe automatic preparation and wider
decimal/binary/temporal/nested batch intake remain separate work. Dynamic
one-shot pivot input rejects before producer demand; ordinary relational pivot
spill does not remove that boundary.

## SQL, nested values and native ownership

Scalar-value subqueries work through SQL and `sl.scalar_subquery(...)`. One
statically bound output column returns a typed NULL for zero rows, the complete
value for one row, and a cardinality error for a second row. Explicit
`outer.<column>` correlation and selected CASE/COALESCE demand retain native
source and resource ownership. Dynamic-pivot-dependent scalar schemas and
lateral relations remain unsupported. See the
[scalar-subquery contract](../architecture/native-scalar-subqueries-2026-10-05.md).

Static List, FixedSizeList and Struct values can serve as admitted pivot indices,
domains and selected cells. Nested first/first_unique, COUNT, MIN and MAX preserve
complete values and shared nested ordering. Python `pivot()` and
`pivot_table(aggfunc="first")` retain the first_unique alias; SQL's explicit first
selects the first row, including NULL. Nested SUM/MEAN, non-NULL nested fill and
nested-index margins remain unsupported. Nested MIN/MAX margins require a UTF8
index. Representable results use native Vortex or admitted writers; CSV emits
quoted JSON text for nested cells and ORC rejects nested output. See the
[nested pivot contract](../architecture/native-nested-pivot-state-2026-10-06.md).

Reviewed FSST/Zstd payload, view and validity buffers retain allocation credits
through native owners, clones and slices. Actual one-shot Zstd decoder and
prepared-dictionary workspaces are admitted before allocation. Primitive,
Boolean and decimal Chunked output, nullable bitmaps and builder finalization
overlap also use the shared memory owner. Malformed FSST row lengths reject
before decoder allocation. These changes cover named allocations; child decoder
and selection scratch, structural metadata, compression/training contexts,
consumer Python retention and other unreviewed allocations remain distinct.
A query grant is not a total-process RSS ceiling.

## Compatibility and support

The Rust workspace, CLI, Python package and website package metadata advance
together. Internal Rust crates remain unpublished. The release preserves the
admitted Vortex 0.85.0 provider graph and existing machine-readable schema version
identifiers. The optional spill policy and default resident behavior retain
their existing public shapes; the additions broaden admitted operation paths.

The Zstd decoder now requires admitted modern or skippable frames with known
content sizes and the pinned linked provider. Legacy Zstd frames that previously
used dynamic decoder allocation reject explicitly; malformed, truncated or
trailing data and a provider-version mismatch also reject without a decoder retry.
See the [decoder compatibility contract](../architecture/native-zstd-workspaces-2026-10-07.md).

Small-result collection remains bounded by 65,536 rows, 128 top-level fields
and 8 MiB. Native Vortex is the highest-fidelity persistence target; compatibility
writers preserve only their declared types and metadata. Unsupported Variant or
extension behavior, nested arithmetic, broader SQL/frame semantics, additional
state spill and wider adapters still return deterministic diagnostics.

The detailed pressure and batch-runtime acceptance is macOS arm64 with Unix
facilities. Hosted builds and package installation checks do not establish
equivalent runtime support on every platform. Production certification,
distributed execution, cloud/table transactions, complete SQL/DataFrame parity,
and the remaining local-workflow/optimization obligations are outside this
technical preview. No external query-engine fallback is introduced.

## Acceptance evidence

The [pivot acceptance](../benchmarks/native-pivot-pressure-2026-10-08.md) records
32,497 public checks and 18,595,284 complete row comparisons, including 3,626
pivot pressure checks and 133 incremental proofs. It also covers the 442-case
streaming suite, direct and adapter regressions, source gates and complete
Full43 results. Native constrained controls and public routes use separately
declared grants; their evidence must not be conflated or added as independent
workloads.

The [fresh October 9 pre-bump UAT](../benchmarks/release-candidate-fresh-uat-2026-10-09.md)
ingests all 99,997,497 rows into a new Vortex artifact and passes all 129 complete
query comparisons. Native ingest takes 52.009961 seconds; the sum of query minima
is 71.470899 seconds. These are unpaired source-build observations, not timings
of the subsequently packaged binaries or a combined end-to-end wall-clock score.
The 18-cohort format matrix passes 1,408 comparison records, including 704 native
records, across all 22 declared workflows. It covers eight inputs with collection
and eight outputs from CSV, each raw and prepared, rather than the full Cartesian
format product. Independent packet inspection preserves complete values,
original reports, failures, source identities and no-fallback boundaries.

Publication, clean installation, uninstall/reinstall, package smoke, checksums,
SBOM and provenance remain separate release-channel evidence. This release makes
no new comparative speedup, process-RSS bound or competitive superiority claim.
