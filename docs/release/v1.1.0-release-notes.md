# ShardLoom 1.1.0 source milestone

Status: source/package version prepared; local 1.1.0 package and hosted
acceptance are pending. No 1.1.0 tag, release or package publication is part of
this milestone. Published installation instructions and channel proofs continue
to identify the immutable 1.0.0 artifacts.

This minor version brings the accepted analytical, direct local I/O, adaptive
resource and preparation work into one source package version. SQL, Python
DataFrame, typed native, embedded workflow and CLI declarations continue to use
the same ShardLoom engine. Vortex remains native input, state and output;
compatibility formats use explicit readers and writers.

## Changes since 1.0.0

- The [connected programming model](../reference/connected-programming.md)
  supports composing SQL and DataFrame declarations in one native plan, with
  query-local sources, explicit parameters and retained results.
- The [analytical program](../architecture/native-broad-query-program-2026-10-26.md)
  adds the admitted temporal, window, relational composition and explicit batch
  function families. Each family's type, effect and resource contracts continue
  to govern support. Remaining program and competitive gates stay separate.
- [Direct local I/O](../architecture/native-universal-io-implementation-2026-10-31.md)
  shares source-demand planning and execution across all five interfaces.
  Ordinary source queries do not depend on an automatically prepared sibling.
  Explicit preparation retains its generation, reuse and publication contract.
  Multiple outputs share one computation and retain independent commit/readback
  evidence.
- [Adaptive execution](../architecture/native-adaptive-acceptance-2026-11-02.md)
  applies shared sizing and concurrency decisions across the declared source,
  operator, spill and output owners within caller ceilings. Physical and
  semantic limits remain explicit. Named reservations are not a promise of
  complete allocator or process-memory accounting.
- [Local table readers](../architecture/native-local-table-readers-2026-11-02.md)
  admit finite Iceberg v1/v2, Delta and Hudi Copy-on-Write snapshot profiles.
  Unsupported visibility, schema and file-layout combinations fail explicitly.
  Catalog discovery, remote table access, table commits and merge-on-read
  remain outside the admitted profiles.
- [Preparation contracts](../benchmarks/native-preparation-contracts-2026-11-02.md)
  reuse consumed writer proofs during immediate publication, emit sparse Zstd
  frame offsets and preserve proven helper nullability through persistence and
  worker admission. Shared-allocation and dictionary-frequency proposals remain
  deferred for missing ownership/domain proof.

The [documentation refresh](v1.1.0-documentation-refresh.md) supplies executable
examples, a local-table guide and updated resource, SQL, Python and I/O guidance.
Its desktop/mobile navigation, search and rendered-layout checks pass locally.

## Compatibility and support

The version change itself adds no execution behavior or machine-schema change.
Existing documented calls keep their contract. Direct-source defaults now use
the original source; request durable preparation explicitly when that is the
intended workflow. The [migration reference](../reference/python-api-migration.md)
retains transport, context ownership, typed-error and result-lifetime guidance.

Python remains 3.10 or newer. Actual built wheel tags and installation proofs
determine platform/ABI coverage. Internal Rust crates remain unpublished.
The [schema stability contract](v1-api-schema-stability-matrix.json) and existing
experimental/unsupported classifications remain authoritative. Unsupported
plans fail explicitly; no external query engine supplies fallback execution.

Rich-data lifecycle is the next planned item 19. Remote authenticated workflows,
Foundry, AI/model operations and new distribution channels retain their own
scope and gates. This source milestone does not grant production support,
performance superiority or broader lakehouse support.
