# ShardLoom v0.3.1

Status: source preparation for a technical-preview release. Publication requires
new GitHub, TestPyPI, PyPI and Homebrew proofs in that order. The selected
published-channel contract remains v0.3.0 until those proofs are complete.

This patch release groups the retained storage, ingest and native execution
improvements after v0.3.0, including whole-document JSON typed construction in
PR #1475. It preserves Vortex-native execution and output, explicit resource
admission, and the no-external-engine-fallback contract.

## Included changes

- Native dictionary persistence keeps bounded source-derived dictionaries in
  Vortex output. The related cross-column storage and incoming source-dictionary
  experiments were screened separately and are not included as new runtime
  behavior. Native sort consumers now use integer and UTF8 sort blocks before
  forming Top-K candidates; the screen does not establish a suite-wide,
  zero-decode or memory-gate improvement.
- Public owned-array composition carries native Vortex arrays through prepared
  aggregate execution while retaining session, cancellation, reservation and
  owner contracts. Serialization into immutable memory-file segments remains an
  explicit boundary. Writer lookahead shares the existing producer input slot,
  without expanding its worker count, configured window or credits. Exact
  DISTINCT numeric updates bind each block's typed measure once, and weighted
  spill validation reuses the owned merge head for predecessor checks.
- Source-order COUNT uses compact chunk-local candidate directories and retains
  exact closed-group updates. A bounded selector can choose the existing direct
  native aggregate path for eligible small integer COUNT requests before worker
  admission. Both changes preserve existing native execution paths and their
  stated admission limits.
- Portable ThinLTO is the ordinary release profile. The tested PGO promotion
  and automatic selection of the tested native-CPU profile were not retained;
  their explicit profile tooling remains separate. The screened Vortex 0.86.1
  provider upgrade was not admitted.
- JSONL preparation builds typed columns using indexed reusable row slots,
  avoiding retained named scalar row maps and a later row-to-column traversal.
  Duplicate-key, inference and native commit behavior remain within the
  existing JSONL input contract; this change does not add general JSON grammar
  or exact-u64 JSONL parsing.

## Screened work not included

The bounded screens did not retain cross-column conditional storage, incoming
source-dictionary persistence, a new FSST consumer, duplicate shared-domain
transform logic, eager shared-producer routing, a second generic native sink
overlap queue, a new AMAC lookup prototype, or a duplicate packed-numeric
comparison kernel/new BitWeaving layout. The existing Vortex packed comparison
provider remains in use. These dispositions are specific to the documented
screens and workloads.

## Whole-document JSON

Whole-document JSON now constructs typed columns through the existing native
writer, preserving first-seen field order, last duplicate-key value, missing/null
backfill, stable inferred types and atomic output publication. Writer batches
retain the same allocation geometry across chunks. The parser and typed columns
still retain the complete document; this is not a streaming-parser memory claim.

## Validation boundary

The accepted pre-bump runtime passed 3,426 workspace tests and 3,512 native
feature tests, with 22 existing manual cases ignored. Full-size acceptance also
includes byte-identical Parquet replacement ingest, 456 held-out public calls,
five spill/pressure/cleanup cases, and all 6,291,456 cells in the JSON fixture.
The [versioned source checks](v0.3.1-source-validation.json) bind source
`30515b5f807aa8d6511ffc5e9ffe9758c7f99a99`: 3,426 workspace and 3,512 native
tests pass (22 existing manual-case ignores), both all-target Clippy checks
pass with warnings denied, and formatting, Python release-proof tests and
version/status/package-contract checks pass. Feature-suite test counts overlap.
These checks include the final two-field ownership-certificate correction from
PR #1475. Subsequent release edits are documentation and history alignment only.

The latest Full43 value check records 129/129 complete results and an unpaired
best-of-three sum of 71.273789 seconds. It is a regression observation for that
build, not a causal comparison or speedup claim. The JSONL and whole-document
JSON ingest measurements belong to separate format-specific screens and must
not be combined with Full43 timing.

## Compatibility and remaining work

CLI, Python, website package metadata and the internal Rust workspace advance
together to 0.3.1. Internal Rust crates remain unpublished and experimental;
machine-readable schema versions and external dependencies are unchanged by
the version bump. Unsupported execution still fails explicitly.

General native joins, set operators, analytic windows, scoped subqueries,
remaining prepared/owned operator paths, broader pressure handoffs and
production-scale concurrent serving remain in the native completion plan.
The seven remaining performance candidates stay queued after this release.

Package access remains a technical preview. This release does not claim production
readiness, competitive superiority, broad SQL/DataFrame parity, object-store,
lakehouse or Foundry support, or external-engine fallback.
