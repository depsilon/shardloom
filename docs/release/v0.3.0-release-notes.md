# ShardLoom v0.3.0

Status: source preparation for a technical-preview release. Publication requires
new GitHub, TestPyPI, PyPI and Homebrew proofs in that order. The selected
published-channel contract remains v0.2.4 until those proofs are complete.

This minor release includes retained query improvements, broader native prepared
aggregates, recoverable spill ownership, bounded resident admission and owned
Vortex result composition since v0.2.4. It preserves the optimized ClickBench
paths and the Vortex-native, no-external-engine-fallback contract.

## Included changes

- Complete triple-key COUNT partitions, weighted integer partition reduction,
  dictionary-domain UTF8 validation and cached hashes, source-order candidate
  filtering, and separate compound lookup directories/dense owned records.
  These are shared native physical paths; admission still checks the complete
  shape and semantics. Failed or immaterial experiments remain excluded.
- Ordinary prepared aggregates reuse existing native lowering for supported
  text, float and null keys/values, triple keys, derived outputs, and supported
  measure transforms. Preparation retains immutable source generations and
  lowering; every call owns fresh execution state. Shape limits are checked
  before projection or state allocation.
- Explicit weighted UTF8 COUNT and integer DISTINCT spill reuse retained
  sources. Native run directories exclude live owners and competing recovery;
  interrupted cleanup is retryable and preserves unknown or replaced files.
  Public cancellation renewal retains the resource policy with a fresh token.
- Explicit resident serving bounds CPU ownership, queue admission and actual
  I/O completion, with cancellable waiting and a metadata lane when capacity
  permits. Default exclusive admission remains the default.
- Owned native batches carry their dtype even for empty results. Native and
  compatibility sinks preserve that schema. Bounded memory-file composition
  retains native columns, normalizes root validity, and exposes a retained
  source to the existing optimized prepared aggregate executor. Construction
  serialization and native completion are reported separately from query work.
- Parent cancellation reaches ordinary prepared aggregate scans and queued
  admission without poisoning independent worker retries. Composed stages
  borrow one resident execution context and drain ownership before returning it.

## Compatibility and remaining work

The CLI/Python package and internal Rust workspace advance together to 0.3.0.
The four internal Cargo path-dependency requirements also advance to the new
minor version. Internal Rust crates remain unpublished and experimental. This
package bump does not promote machine-readable schemas to stable status.

New Rust composition/serving controls do not establish equivalent public
SQL/DataFrame support for every family. General native joins, set operators,
analytic windows, scoped subqueries, remaining prepared/owned operator paths,
broader compound/DISTINCT pressure handoffs and production-scale serving
acceptance remain in the native runtime completion plan. Parent cancellation
inside explicit spill stages remains a separate obligation; those stages retain
their policy cancellation token and observe the parent at their boundary.

Composition has explicit row, field, batch, segment and byte limits. Native
serialization may copy and complete layouts; no universal zero-copy or
zero-decode claim follows. Scoped reservations are not a process-RSS guarantee,
and generation validation is not an atomic filesystem snapshot. The tested
spill namespaces and cleanup policy are not universal spill support.

## Validation boundary

The pre-bump implementation acceptance is documented in
[native result composition](../architecture/native-result-composition-2026-09-20.md)
and [native runtime completion](../architecture/native-runtime-completion-2026-09-20.md).
The frozen runtime at `534095f78cc50c910e585c250979f432e2bad7f1` passed:

- Full43: 129/129 complete results over 99,997,497 rows. The sum of per-query
  best-of-three times was 63.459160 seconds, including fresh CLI startup,
  complete output and exit. This unpaired observation is not a causal speedup
  comparison or a benchmark of published 0.3.0 artifacts.
- Public-call UAT: 2,232/2,232 complete calls across fresh CLI, persistent worker
  and Python routes, with independent fixture values and reuse assertions.
- Held-out operators: 760/760 calls across 19 cases and five worker requests;
  720 complete-value oracle checks and 40 expected overflow diagnostics.
- Workspace/native tests, Clippy, formatting, bounded serving lifecycle checks
  and the documented ownership/cancellation/spill boundary tests.

Historical fresh ingest remains 95.923669 seconds and 18,591,586,804 bytes.
It has not been remeasured for this train. Full-size runtime UAT will not be
relabeled as package-channel proof. Release artifacts require their own version,
install, complete-result smoke, uninstall, checksum and provenance verification.

The [versioned source record](v0.3.0-source-validation.json) binds the 0.3.0
checks to `89e57fe3`: 3,425 workspace tests, 3,435 native tests (ten explicit
manual-case ignores), both all-target Clippy configurations with warnings denied,
and formatting pass. Subsequent changes are documentation and a history-only
merge. Counts overlap between feature configurations. Four Python version tests
and the version/public-status/package-contract checks also pass. These source
checks do not constitute channel installation proofs.

Package access remains a technical preview. Production readiness, competitive
superiority, broad SQL/DataFrame parity, object-store/lakehouse/Foundry support
and additional distribution channels remain outside this release's claims.
