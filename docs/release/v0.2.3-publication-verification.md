## Registry Build Recipe

The first TestPyPI attempt, workflow `33978578712`, was cancelled before publication
after identifying an existing macOS wheel-label defect. Wheel's macOS platform
recalculation can discard the package hook's post-finalization assignment and use
the Python interpreter's universal2 label, despite a single-architecture CLI.

The release staging recipe now supplies an explicit bdist_wheel platform option
and aligns the existing package override with that option. It conservatively
uses the configured macOS deployment target (when supplied), otherwise the build
host's macOS major release, and the actual architecture. No engine,
Python runtime, package setup source, published GitHub asset, or release tag is
changed by this recipe correction.

Real build reproduction with `_PYTHON_HOST_PLATFORM=macosx-10.13-universal2`:

- Before: `shardloom-0.2.3-cp313-cp313-macosx_10_13_universal2.whl`.
- After: `shardloom-0.2.3-cp313-cp313-macosx_26_0_arm64.whl`, with matching WHEEL
  metadata, successful clean install, bundled-CLI smoke, and uninstall.
- Python discovery: 786 tests, 144 existing skips, no failures. Focused tests cover
  arm64, x86_64, macOS major-version normalization, preserved configuration,
  non-macOS no-op behavior, invalid platform failure, and package builder options.
