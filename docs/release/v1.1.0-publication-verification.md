# ShardLoom 1.1.0 publication verification

ShardLoom 1.1.0 is available as a technical preview through GitHub, TestPyPI,
PyPI and Homebrew. Install Python with `python -m pip install shardloom==1.1.0`
or the CLI with `brew install depsilon/tap/shardloom`.
[Install and query local data](https://shardloom.io/field-guide/start-local-proof).

target macOS 26 or later on ARM64 and Linux x86_64 with glibc 2.39 or later.
The CPython 3.13 Windows x86_64 wheel runs the bundled CLI through subprocess
transport. The source distribution contains Python sources. The separate wheel
attached to the GitHub release targets macOS 27 or later on ARM64.
[TestPyPI provenance](channel-proofs/testpypi-v1.1.0-provenance.json) ·

The observed build artifacts matched the SHA-256 and size of all eight registry
distributions. The four Linux and macOS installed-test logs each contained all
303 named tests from 33 release-source modules, with zero skips, errors or
failures. Both Linux portability audits preserved 290 payloads. The 13
observation-extension tests ran separately in source CI.

The package metadata on all ten inspected GitHub and registry Python
distributions identifies version 1.1.0. Their embedded READMEs captured the
previously selected 1.0.0 install command before the publication sequence.
Use the 1.1.0 command above for this release.

## Runtime checks

The tagged example ran in isolation with the downloaded GitHub wheel and its
bundled CLI. DataFrame, Python SQL, typed native, embedded workflow and CLI SQL
each returned IDs 2 and 3 in order. The example also verified explicit Vortex
preparation and reopened both destinations of a single shared write.
[Example](https://github.com/depsilon/shardloom/blob/v1.1.0/examples/source-interfaces/run.py) ·
[Installed-wheel result](evidence/v1.1.0-published-five-interfaces.json).

The downloaded CLI passed three golden workflows and nine stages. An earlier
run in a second checkout returned the correct values and native I/O evidence,
but its three primitive stages could not issue the fixture-specific correctness
certificates. The verifier binds that fixture to its canonical path in the
compile-time checkout. The passing run used that path and verified the fixture
and Python client against the tagged source. Both attempts are preserved.
[Golden report](evidence/v1.1.0-published-golden-workflow-report.json) ·
[Executable and source identity](evidence/v1.1.0-published-golden-workflow-identity.json).

Homebrew built the CLI from the published source archive. Its supplemental
Python workflow explicitly selected that CLI and loaded the Python extension
from the verified PyPI wheel. The first verifier expected a retired CLI field.
The second validated the ordered JSONL result, schema, formula, linkage and
complete workflow, then interrupted pip when a temporary file disappeared
during the storage scan. The final verifier retries the entire scan when pip
removes an entry in its own virtual environment and requires every resource
and identity check to pass. The transcript links both earlier attempts.
