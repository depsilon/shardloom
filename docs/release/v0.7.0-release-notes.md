# ShardLoom v0.7.0

Status: technical-preview release candidate. Source, package and selected-channel
acceptance are being prepared. The verified published package remains v0.6.0
until the new GitHub, TestPyPI, PyPI and Homebrew proofs are complete.

This minor release packages the application context and result API, finite
streaming and spill extensions, resource ownership corrections, and consistent
native strategy selection across admitted file formats. SQL, Python, DataFrame
declarations and the CLI continue to use the shared Vortex-native engine.
Unsupported execution fails explicitly; no external engine executes residual
work.

## Migration: context execution and typed results

`sl.context(...)` now selects its installation backend once. A Linux or macOS
native installation defaults to in-process execution. Windows and explicit CLI
configuration select process execution. Set `transport="subprocess"` when an
application needs process isolation. The lower-level `ShardLoomClient()` retains
its existing process default. A missing selected backend or execution error
does not trigger another backend or automatically replay the request.

Contexts support `with`, `close()`, `cancel()` and `closed`. Collection returns
`Result`, exposing an ordered schema, explicit `to_rows()` and optional conversion
methods, and typed execution details. `ctx.from_result(result)` admits retained
ShardLoom data through the existing owner boundary without compulsory Python-row
or Arrow export on the native path. Completed result values remain available
after the context closes. Cross-owner admission may copy; process result
admission uses its bounded typed payload.

Execution helpers raise typed errors by default. Callers deliberately inspecting
unsuccessful reports must pass `check=False` and check `is_error` before using
values. The previous result class name remains an identity alias, and legacy
named root imports remain available through compatibility lookup. Application
completion is curated; inspection and fixture types live in
`shardloom.diagnostics` and `shardloom.testing`. The package includes type stubs
for these namespaces and the application API.

Memory and parallelism remain explicit caller choices. Existing result-size,
batch delivery, spill authorization and destination contracts still apply.
Process batch pipes require POSIX; Windows retains bounded collection and
writers. See the [migration reference](../reference/python-api-migration.md)
and [application acceptance](../architecture/public-documentation-api-acceptance-2026-10-18.md)
for examples, lifetimes, diagnostics and compatibility details.

## Shared native strategy selection across formats

Equivalent admitted file inputs now normalize before native provider selection.
Ordinary SQL and embedded plans preserve the complete operation, declared source
format and preparation ownership. Queries against compatibility files can use
the same applicable count, filter, aggregate and ordering providers as their
prepared Vortex representation. Existing preparation is reused when its source,
schema and artifact generations remain valid.

Count and filtered-count writes hand their typed scalar to the existing sinks
without changing the count producer. Metadata-only counts retain their source
work avoidance. Writer reports preserve the sink policy and the producer's
scan evidence separately. Wildcard readback of the original Parquet/ORC failure
fixtures now agrees with the native public schema. Explicit Arrow IPC
declarations work with opaque filename extensions, and source rebinding
preserves matching string literals.

The [format acceptance](../architecture/native-format-strategy-parity-2026-10-21.md)
records complete values, provider parity, all eight existing sinks, source
changes, preparation reuse and the separate review regression. Format-specific
parsing and serialization remain boundary adapters. This change does not claim
a first-use preparation speedup or universal type/operator support.

## Finite streaming and native spill

Finite streaming plans extend through compatibility destinations, set and unary
operations, and admitted static/dynamic subquery composition. Original producers
are consumed according to the shared replay contract. Late producer errors,
cancellation and invalid generations prevent successful completion or final
publication. Existing destination and multi-output failure contracts remain;
multi-file atomic publication is not newly promised. See the
[destination](../architecture/native-stream-destinations-2026-10-15.md),
[set](../architecture/native-stream-set-operations-2026-10-15.md),
[unary](../architecture/native-stream-unary-2026-10-15.md) and
[subquery](../architecture/native-stream-dynamic-subqueries-2026-10-15.md)
contracts.

With explicit spill permission, shared relational membership state now completes
the admitted `UNION`/`INTERSECT`/`EXCEPT`, distinct/deduplication/duplicate-mask,
and `IN`/`EXISTS`/quantified `ANY`/`ALL` pressure workloads. Six weighted and
unweighted sampling population variants also complete under their original
pressure grants. Resident algorithms and the bounded nonreplacement sampling
strategies retain their existing semantics. The accepted paths use ShardLoom
native run storage and Vortex providers, with quota, generation, cancellation
and cleanup checks.

These are finite operator contracts. They do not make all state spillable or
establish a total-process memory ceiling. Process-death coverage proves owned
abandoned-state cleanup and fresh execution, not resuming an interrupted query.
See the [set](../benchmarks/native-set-membership-spill-2026-10-18.md),
[unary](../benchmarks/native-unary-membership-spill-2026-10-18.md),
[subquery](../benchmarks/native-subquery-membership-spill-2026-10-19.md) and
[sampling](../benchmarks/native-sampling-population-spill-2026-10-19.md)
acceptance records for exact workloads and limits.

## Resource ownership and shared execution

Native structural storage is admitted before allocation for six covered classes:
child caches/classification, cumulative row offsets, reader metadata vectors,
segment specifications, file statistics tables, and user metadata names/locators.
Credits remain with the actual shared owner through independent aliases and
final release. Native segment slicing also handles valid offsets with weaker
alignment than the backing buffer. The
[structural acceptance](../architecture/native-structural-provider-acceptance-2026-10-21.md)
states the remaining reader, codec, schema and allocation boundaries.

Shared text aggregation, validity, reconstruction and scan reuse retain their
accepted source and workload evidence. Rejected optimization experiments remain
rejected; the release does not ship their abandoned candidates or infer a
general speedup from isolated query observations.

## Acceptance and remaining scope

The final format acceptance completed one isolated Full43 pass: one execution
of each of 43 queries, all 381 result rows validated, and **48.754238077 engine
seconds**. This is a source-build regression observation with its original input,
reference, commit and executable identities. It is not a measurement of the
subsequent v0.7.0 packages, a paired speedup claim, or a raw-format preparation
measurement. The later writer-report correction does not affect that collect
path; the pass was not repeated for the version change.

Release packaging and published-channel installation require their own fresh
proofs. Linux x86_64 and macOS arm64 native wheels retain the `cp310-abi3`
contract; the Linux wheel requires its declared manylinux audit. Windows retains
the CLI-backed package. The clean source distribution contains no native binary.
Internal Rust crates remain unpublished, and the other package channels remain
blocked until separately proved.

Release source archives omit compressed benchmark evidence bundles and their
multipart chunks so installation does not download the historical proof payloads.
Source code, build manifests, vendored fixtures, license texts, evidence indexes
and replay scripts remain included. Use a Git checkout at the recorded source
revision to replay evidence that needs an omitted bundle. The release verifies
the exported file identities and builds the CLI from the unpacked archive.

The support label remains a local technical preview with operational hardening
in progress. Production certification, broad SQL/DataFrame parity, distributed
execution, cloud/table transactions, Foundry support and competitive superiority
are not claimed. Vortex remains native input and the highest-fidelity output.
