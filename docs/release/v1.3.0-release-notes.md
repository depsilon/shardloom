# ShardLoom 1.3.0 release notes

Version `1.3.0` consolidates accepted engine, SQL binder, resident I/O, spill,
rich-type, workflow, and multi-table verification work on `main` since `v1.1.0`,
and is published and verified for technical-preview installation across GitHub
pre-release assets (`v1.3.0`), TestPyPI, PyPI, and `depsilon/homebrew-tap`
([publication verification](v1.3.0-publication-verification.md)).

## Changes since v1.1.0

- **Pure-AST SQL binder and converged relational execution (`E2E-ARCH-02`, `E2E-PERF-05A`, `E2E-PERF-05B`)**:
  Replaced handwritten SQL string splitters with one canonical `sqlparser`
  (`0.64.0`) pure-AST binder in `shardloom-plan::sql_binder` (`ShardLoomSqlDialect`),
  converging SQL and Python `LazyFrame` pipelines onto native N-way hash joins
  (`INNER`, `LEFT`, `RIGHT`, `FULL`, `LEFT SEMI`, `LEFT ANTI`, `CROSS`),
  partitioned analytic windows, uncapped set operations, reusable
  `Plan::Materialized` CTEs (including `AS NOT MATERIALIZED`), decorrelated
  semi/anti/scalar subqueries, `QUALIFY`/`FETCH`, compiled columnar batch
  expressions, pushed post-join conjuncts, and build-side min/max/`InList`/3-bit
  Bloom scan runtime filters.
- **Vortex metadata aggregates, resident layout caching, and high-throughput spill (`E2E-FIX-01`, `E2E-PERF-01`..`04`, `E2E-PERF-05C`, `E2E-PERF-06`)**:
  Added exact Vortex footer metadata aggregate completion, exact `i128`
  integer `SUM`/`AVG` accumulation, cross-query `ResidentLayoutSlotPool` and
  `LayoutReader` caching across prepared sources, gated `SegmentPrefetchPolicy`
  coalesced byte-range I/O, unified session-persistent `ComputePool` scheduling,
  content-driven `FirstBatchProfile` readers, direct `VarBin`/`VarBinView` Zstd
  encoding without canonical inflation, `OwnedVortexResultBatch` direct sinks,
  binary length-prefixed Arrow IPC worker framing, and `16K`–`64K` streaming
  native Vortex spill blocks with single-pass write digests.
- **Rich columns, deep traversal, and optional workflow adapters**:
  Added native workflow support for dense `Float16`/`Float32`/`Float64` vectors,
  declared embedding identity, fixed- and variable-shape tensors, sparse
  coordinates, affine quantization codes, inline binary values, nested variants,
  and resource-admitted depth-24 nested traversal (`RFC 0045` partial native
  coverage), plus optional `shardloom.ai`, Foundry transform adapter, and
  `RFC 0047` portable serverless worker foundations.
- **Multi-table TPC-H and SSB suite and optional allocator intake (`E2E-VERIFY-03`, `E2E-PERF-00`, `E2E-PGO-01`)**:
  Added deterministic 8-table TPC-H (`8` queries) and 5-table SSB (`6` queries)
  offline dual-reference verification (`python_reference` and `sqlite3_sql`),
  optional non-default `cli-mimalloc` (`mimalloc = 0.1.52`) isolated in
  `shardloom-cli`, and post-unification ThinLTO PGO training/coverage gating
  with `[profile.release]` kept unchanged (`default_release_profile_changed=false`).
- **Modularization and dependency hygiene (`E2E-ARCH-01`, `vortex 0.93.0`)**:
  Extracted `shardloom-bench`, split large test modules into thin facades,
  converted internal key-value evidence bags to typed `serde` structs, and
  updated upstream dependencies to `vortex = 0.93.0`, `PyO3 = 0.29.3`, and
  Arrow `59.3.2`.

## Compatibility and support

- Python keeps the `shardloom.connect()` / `Context` / `Result` surface, lazy
  composition, binary Arrow IPC or JSON session worker transport, and
  `cp310-abi3` native Python module on Linux and macOS (CLI-backed Python
  transport on Windows).
- `100M` external ClickBench baseline and PGO screens remain open offline/mounted-dataset
  gates; this source milestone records `new_benchmark_observations=0` at `1.3.0`
  and preserves prior pre-bump `3931f6473` TPC-H/SSB `scale_rows=12000`
  engine-time measurements (`0.101878042s` cold / `0.085962461s` warm Vortex;
  `0.039211251s` cold / `0.032298748s` warm Parquet across `14/14` queries)
  as source history only.
