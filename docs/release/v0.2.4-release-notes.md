## Included Changes

The train incorporates retained work since v0.2.3 that is already on main:

- Keeps admitted numeric aggregates on typed native accessors and retained
  encoded owners, including narrow integer keys, dense additive run-end
  consumers and exact aggregate entry admission. Defers whole-tree layout
  inventory until a consumer requires it.
- Uses bounded aggregate chunk jobs and complete key partitions for admitted
  COUNT and integer DISTINCT work. Provider admission denial restores the
  original native scan driver. Worker activity, materialization and ownership
  reports distinguish actual work from configured or selected contracts.
- Extends generation-checked resident execution, prepared aggregate and scan
  reuse, and immutable addressable native-memory generations. Each query owns
  fresh execution state; preparation does not cache answers. Native owned
  integer DISTINCT results can outlive their input and use the existing
  Vortex, Arrow IPC and Parquet result writers.
- Retains explicit native spill for its admitted sort, integer DISTINCT and
  weighted COUNT families. Pressure handoffs drain workers, transfer committed
  state once and preserve exact remaining-input accounting. Unsupported shapes
  fail explicitly; spill is not enabled for every query family.
- Improves native ingest ownership, conversion prefetch, numeric encoding
  preservation and stage accounting. Unix Parquet intake carries held source
  identities through pulls, EOF and final prepublication checks. Explicit
  overwrite and staged publication policies remain in place, and
  cancellation/pressure cleanup keeps the existing ownership and output
  boundaries. The parked publication-race extension is not included.
- Keeps metadata proofs conservative when facts are absent, approximate or
  contradictory. Complete-result, source-generation and output-lifetime
  regressions accompany the retained changes. Resident worker tests are part
  of the native public-surface CI lane.

The final performance PR adds four selected families to that retained base:

- Exact `COUNT(DISTINCT integer)` grouped by one nonnullable UTF8 identity key.
  Complete text/value pairs meet in shared native partitions before EOF group
  counts and global count/text ordering. All eight integer widths preserve
  signedness and exact bits. This extends the ordinary result path; it adds no
  owned or retained UTF8 DISTINCT API and no UTF8 DISTINCT spill.
- Owned native COUNT(*) results for one nonnullable integer identity group.
  The existing prepared API preserves the original integer key width and
  emits U64 counts without building grouped JSON or StatValue output rows.
- The corresponding prepared and owned COUNT(*) path for one nonnullable UTF8
  identity group. Native VarBin output copies only selected key bytes and
  retains its buffer and metadata reservations through children and slices.
  Both owned COUNT families require a nonnullable source Struct, bounded
  count-descending/key-ascending selection, at most 65,536 prefix rows and
  at most 8 MiB of native output buffers.
- Exact unfiltered global integer MIN/MAX/COUNT completion from the already
  held Vortex file footer when every requested measure has sufficient exact
  evidence. Missing or inexact statistics retain the existing native scan;
  contradictory facts fail explicitly. NULL, empty, aliases and HAVING keep
  their normal result semantics. SUM/AVG and grouped/filter/spill requests do
  not acquire this footer-only route.

These changes preserve native Vortex input/output and the existing pinned
Vortex 0.85 provider boundary. Compatibility formats remain explicit adapters
and sinks. No external query engine executes unsupported ShardLoom work.

## Compatibility and Scope

The inherited public Rust struct `FlatLocalColumnarStreamSource` now requires
`source_identities`. Direct struct literals must supply the field; custom
in-memory sources may use `source_identities: Vec::new()`, which does not certify
immutability. Preserve identities when wrapping an adapter-produced source.
Prefer the existing Parquet stream constructors for automatic Unix guards.
See `docs/reference/resident-native-results.md` for this source migration and
the platform limits. The workspace Rust crates remain unpublished.

The four selected additions reuse existing requests, APIs and output schema
versions. A package-version update is not a protocol/schema-version update.
Feature gates and explicit unsupported diagnostics remain in force. Generation
checks are not atomic filesystem snapshots; scoped reservations are not a
process-RSS guarantee. Owned output avoids row construction, not all decoding
or copying throughout a query.

This train excludes the regressing nullable prepared-minute worker admission,
the slower experimental text-storage replacement, new compound owned COUNT,
additional owned measures, nullable UTF8 COUNT, new UTF8 DISTINCT spill,
experimental join/window/projection APIs and further codec portfolios. Their
saved experiments do not become release capabilities.

## Measurement and Verification Boundary

Combined implementation UAT passed before PR #1443 opened. The
[acceptance report](../benchmarks/combined-performance-uat-2026-09-12.md)
binds exact binaries, inputs, commands, clocks and preserved failures.

- Fresh ingest: 99,997,497 rows in 95.923669 s; 18,591,586,804 native bytes.
  Every value across 112 columns and all 560 loaded footer-statistic slots
  matched the protected reference.
- Full43: 129/129 exact results; per-query best-of-three sum 91.825940 s,
  hot minimum sum 92.488320 s, all 129 native durations 281.793539 s.
- The matched Q14/control gate passed: Q14 medians 7.968275 → 1.554247 s.
  Q35's +4.06% paired median/+16.39% worst pair and Q17's +11.78% worst pair
  remain visible. No general timing-stability claim follows.
- 552 owned-result calls, 96 renamed DISTINCT calls, 460 held-out calls
  (440 complete values plus 20 expected overflow diagnostics), 64 matched
  queries and nine public CLI/Python session calls passed.
- Formatting, workspace/native/minimal Clippy and focused tests passed;
  3,417 default and 3,321 native tests passed, with nine existing manual
  fixtures ignored. Those feature-matrix counts overlap.
- The first log-limited Full43 attempt retained 86 validated results and
  was excluded from the new complete run. Verified lossless archival and
  explicitly recorded reproducible-payload retirement restored headroom
  without raising resource limits.

These are pre-bump implementation proofs. The separate
[0.2.4 source validation](v0.2.4-source-validation.json) records passing version,
manifest and documentation contracts, four Python version tests, formatting,
workspace Clippy, 3,417 workspace tests and 3,321 native tests (nine existing
manual cases ignored) on `fbef962589a9bced0ef179ff2cb05cf1dca6434c`.
It does not reuse the 0.2.3 binary as a 0.2.4 package artifact.
Registry installs, package smoke, supply-chain
provenance and publication proofs remain separate. Existing remote CI
requirements are unchanged. The architecture tracker retains its open items.

Previous measurements justify selecting these implementations and remain
attributed to their own frozen binaries and workloads. In particular,
`4730003f`'s Full43 102.005509-second observation is not a measurement of this
combined train. The historical 91.215296-second control and earlier isolated
numeric-ingest observations are not replaced here. Owned-result comparisons
measure JSON versus native result construction within one binary; they are not
whole-workload speedups. Keep those receipts and all raw samples unchanged.
