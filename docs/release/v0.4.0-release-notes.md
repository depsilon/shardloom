# ShardLoom v0.4.0

Status: source preparation; not published. The selected, verified installation
channels remain at 0.3.3. Hosted acceptance of the native composition stack and
the website dependency advisory gate remain open. A source version change does
not establish release-channel installation or publication proof.

The 0.4.0 source candidate expands complete SQL and Python/DataFrame
workflows over the shared Vortex-native runtime. It carries native results
through composed operators and local writers, broadens exact scalar types and
expressions, and makes operation resource ownership explicit. Unsupported
execution still fails without an external query-engine fallback.

## Included changes

- Relational joins, set operations, analytic windows and scoped subqueries use
  native key state, source ownership and result delivery. Existing scalar and
  unary families compose through the same native plan and resource grant.
- Complete local writes consume bounded native batches above the small-result
  collection limit. Native Vortex remains the highest-fidelity persistence target;
  compatibility outputs report their format-specific fidelity and admission.
- Static nested lists, fixed-size lists and structs retain selected native
  payload ownership. Repeated explode and execution-scoped scalar pivot schemas
  compose with admitted downstream operations and representable writers. Native
  fixed-size-list fidelity is covered by typed fixtures; compatible public input
  normalization does not promise to retain a fixed-size declaration.
- Binary, exact Decimal128, Date32 and timezone-free microsecond timestamp
  payloads retain their logical types, including admitted nested leaves. Flat
  comparisons, hashing, ordering, relational keys and COUNT/DISTINCT/MIN/MAX
  use shared exact semantics.
- Static List/FixedSizeList/Struct keys extend equality, hashing and ordering
  through existing relational join, set, group, sort, window and subquery
  kernels. COUNT/COUNT DISTINCT/MIN/MAX and scoped comparisons, NULL tests and
  selected CASE/COALESCE/NULLIF results use these keys. Exact recursive schema
  compatibility includes names/order, widths, decimal metadata and temporal
  identity while ignoring recursive nullability. Selected nested values also
  support DISTINCT/duplicate selection and masks, tail, sampling, parent-level
  forward fill (child NULLs do not trigger filling), lossless same-shape melt
  and rolling COUNT. See the [nested key
  and retained-state contract](../architecture/native-nested-keys-state-2026-10-04.md);
  [local acceptance](../benchmarks/native-nested-keys-state-full43-2026-10-04.md)
  passes, while hosted acceptance remains pending.
- Typed literals, explicit CAST/TRY_CAST, exact decimal arithmetic and rounding,
  binary decoding/length and checked calendar functions bind through the same
  expression engine. Python Decimal values declare native literals rather than
  evaluating query arithmetic in Python.
- Binary, Decimal128, Date32 and timestamp payloads and keys extend the existing
  unary selectors, tail/sample, replacement/forward-fill, lossless melt, rolling
  COUNT and scoped pivot first/first-unique/COUNT state. Typed Python declarations
  and CLI literals use the same native binding and checked conversion rules.
- Ordering can use explicitly enabled, quota-accounted native runs, with shared
  cleanup and complete typed output. Source generation checks, cancellation,
  retained-buffer lifetime and writer publication stay within the operation.
- Ingest selects its local CPU grant from the caller's allocation and available
  capacity. Admitted source, conversion, statistics, codec and writer tasks can
  share ready work instead of reserving idle stage workers. Memory admission
  can narrow concurrency; the grant is not a process-RSS guarantee.
- Native sort preparation reuses decoded column owners, and operation-scoped
  file reads retain live Vortex segment-request sharing. Metadata-only count
  evidence keeps one authoritative field owner and explicit no-fallback proof.

## Compatibility and limits

The Rust workspace, CLI, Python package and website package metadata advance
together to 0.4.0. Internal Rust crates remain unpublished. Source preparation
keeps the existing dependency graph and admitted Vortex provider version. The
version bump itself does not change machine-readable schema version identifiers.
Existing stable v1 report fields remain subject to their additive compatibility
contract; new source-built functionality does not imply package availability.

Decimal arithmetic with integer operands derives precision from the declared
integer width and signedness, rather than the current value. Reference Int64 and
UInt64 operands therefore contribute precision 19 and 20. Output precision and
scale are stable across rows and empty input; combinations exceeding Decimal128
precision fail at binding. Explicit decimal downscaling succeeds only when every
discarded digit is zero. Text-to-decimal retains its stricter fractional-digit
policy. These type and failure semantics are an intentional 0.x compatibility
change.

Expanded unary rewrite and pivot literal fields in unpublished Rust requests
now use the existing `ScalarValue` model instead of `StatValue`. Predicate
declarations keep `StatValue`; original primitive CLI/Python literal meanings
remain compatible. See the [typed unary declaration contract](../architecture/native-typed-unary-2026-10-03.md#declaration-compatibility)
for affected fields, exact JSON forms and decimal reshape/fill semantics.

Decimal CASE/COALESCE branches derive a lossless common precision and scale from
their declared domains, including Python Decimal null-fill. Selected values use
checked casts; impossible common domains fail before execution, including empty
input. Reference and native UInt64 conversions share signedness and range checks.
Float-to-integer conversion requires integral values below the exclusive upper
bounds `2^63` and `2^64`; nonfinite sources remain admission failures for both
CAST and TRY_CAST.

Calendar formatting and checked conversion cover the admitted storage ranges.
Date parsing retains years 0001 through 9999; timestamp input admits Z or fixed
offsets, with no named timezone or general interval support. TRY_CAST turns only
admitted conversion failures into NULL; memory, cancellation and binding failures
still fail the operation. Unsupported-input diagnostics can be more precise as
expressions reach the shared binder.

Collection retains the 65,536-row, 128-top-level-field and 8-MiB limits. General
Variant/extension operations, structured literals, nested arithmetic/string
operations, scalar pivot restrictions, richer aggregate/window semantics,
broader adapters, general state spill/recovery and complete
reader/provider-scratch/RSS accounting remain open. ORC still rejects
decimal/temporal output, and nested CSV/ORC remains unsupported. Remote and
effectful operations keep their existing
policy boundaries.

## Evidence

The [nested-key/state acceptance](../benchmarks/native-nested-keys-state-full43-2026-10-04.md)
records frozen 0.4.0 source `d65907f6`: 17,458 public checks/14,143,015 complete
row comparisons, including 8,162 new checks/17,270 rows from 406 independent
declarations; 202 direct-unary checks; and 25 local gate categories. All 258
paired Full43 results and six Q28 repeats match. No aggregate or RSS threshold
is crossed; the initial Q28 timing gain does not reproduce. Independent packet
inspection verifies original envelopes, complete values, native resource proof
and all four interrupted public attempts. Local acceptance does not establish
a speedup or hosted completion.

The [typed-unary acceptance](../benchmarks/native-typed-unary-full43-2026-10-03.md)
records frozen 0.4.0 source `948551d4`: 9,300 public checks/14,125,745 complete row
comparisons, including 2,700 new unary checks/5,412 rows; 202 direct-unary checks;
and 25 local gate categories. All 258 paired Full43 and 18 reversed-order results
match. Aggregate thresholds are not crossed; Q9 timing/RSS remains inconclusive,
with all observations retained. The immutable packet also preserves independent
oracles, route-specific reservation evidence and interrupted public attempts.
Local functional acceptance does not establish a speedup or hosted completion.

The [typed-expression acceptance](../benchmarks/native-typed-expressions-full43-2026-10-03.md)
records frozen pre-bump review source `895a45c9`: 6,600 public checks and 14,120,333
complete row comparisons, 202 direct-unary checks, 24 local gate categories,
and 258 paired Full43 comparisons without a timing, RSS or aggregate regression
threshold crossed. Its report links the immutable review packet, preserves the
original acceptance and distinguishes independent expression expectations from
retained-result regression evidence. Earlier composition, resource, nested,
pivot, payload and key units retain their own reports and exact scope.

The same report separately records decoded-reference source `7a97a0c5`: seven
core regressions and four native/reference conformance tables, with all 24 local
gate categories passing. This validates lazy CASE/COALESCE, declared nullable
types, decimal branch promotion and UInt64 operations in the shared evaluator,
including its explicit row-based local-source diagnostic path. Native kernels,
binder and public workflow fixtures remain unchanged; the earlier public and
Full43 observations retain their original source and executable identities.

The [source validation record](v0.4.0-source-validation.json) and its portable
packet cover clean 0.4.0 source `cdc6b661`, all 20 local gate categories and 820
unchanged source fingerprints. A fresh release executable and the Python package
both report 0.4.0. Twenty declared-schema cases pass across all eight local
writers, fanout and preparation reuse, with complete readback and no-fallback
checks. Independent inspection reopens the packet and verifies its source,
binary, raw logs, result counts and linked historical evidence. Hosted acceptance
and 0.4.0 installation-channel proof remain pending.
Runtime comparisons remain tied to the recorded binaries and sources; they are
not re-labelled as 0.4.0 package timings.
The current work makes no general speedup, production-readiness or competitive
superiority claim. Paused large-format/text performance campaigns and native
Python binding experiments remain outside this release preparation.
