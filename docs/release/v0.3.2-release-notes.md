# ShardLoom v0.3.2

Status: published technical preview through GitHub pre-release, TestPyPI, PyPI
and Homebrew. See [publication verification](v0.3.2-publication-verification.md)
for release and registry build identities, artifact hashes and installation proof.
The source-validation and pre-bump runtime records below retain their original scope.

This patch repairs public input/output integration and removes redundant work at
native execution handoffs. SQL, Python, DataFrame and CLI calls continue through
the shared Vortex-native execution families, with no external query-engine fallback.

## Included changes

- Complete typed aggregate and sorted results reach the existing format writers
  without serializing and reparsing JSON or executing the query again. Existing
  specialized owned-result finalizers remain in place. Other flat results use
  bounded scalar-to-native construction with explicit schema and memory admission.
- Automatic compatibility-input preparation validates embedded source and artifact
  identities, allowing unchanged inputs to reuse their prepared Vortex artifact.
  A held artifact generation spans execution and evidence construction. Stale or
  unbound artifacts fail explicitly, and unrelated files are preserved.
- Declared Python schemas pass to preparation and execution in one public CLI
  call. Schema declarations participate in preparation identities, preserving
  numeric-looking strings and preventing reuse under a different declaration.
  Prepared calls retain executable SQL alongside descriptive operation summaries.
- Sparse dictionary consumers select referenced values through native Vortex
  providers before materializing text. Reader evidence uses the existing envelope
  certificate path instead of copying complete executable value batches solely
  for diagnostic validation.
- JSON-array exports use the existing bounded text renderer. CSV reads quoted
  multiline records consistently across inference and streaming. Format writers
  retain explicit type, nullability, metadata-loss and atomic-publication contracts.

## Validation and timing

The final implementation commit passed 3,436 default workspace tests, 924
release-feature CLI tests and 1,987 native tests, with 22 existing native cases
ignored. Python validation passed 668 tests with 144 existing skips. Default and
release workspace Clippy, minimal-feature Clippy and formatting passed. Counts
overlap across feature configurations. Small public checks included 110 general
format cases and a later 20-case declared-schema regression pass across all eight
exposed output formats. Exact source and distribution proofs are recorded
separately during this release train.

The authorized plain-Vortex retry passed all 172 query/collection/export cases,
including 129 complete export readbacks. The 43-query collection total changed
from 330.04s in the saved baseline to 104.73s; Vortex export changed from 328.22s
to 106.16s. Each query used one sample per route. These are complete CLI-call
observations from the frozen handoff build, before the final correctness review
fixes and version bump. Uncontrolled cache state and different build identities
prevent an isolated causal speedup or input-format ranking claim. See the
[comparison record](../architecture/plain-vortex-format-comparison-2026-09-27.md)
and [integration contract](../architecture/public-io-route-repair-2026-09-27.md).
No full-size benchmark is repeated for this version-only release step.

## Compatibility and boundaries

CLI, Python, website package metadata and the internal Rust workspace advance
together to 0.3.2. Internal Rust crates remain unpublished. External dependency
versions and machine-readable schema versions do not change in the version bump.

General completed results remain bounded to 65,536 rows, 128 fields and 8 MiB.
Aggregate preflight reserves memory before constructing scalar rows; conservative
string bounds can reject an output whose final selection would have been smaller.
Sort output retains its completed-value check. Format-specific limitations remain
explicit, including unsupported nested/extension outputs and unsigned values that
Avro or ORC cannot represent. This is not every-operator/every-sink parity.

Native Vortex preparation still preserves an existing input layout. The shared
all-I/O layout-optimization policy remains follow-up work; this release does not
make every input or result produce the same optimized physical layout. Parsing,
encoding and scalar result construction still have costs. The interrupted
optimized-reference comparison and large text-format performance tests remain
paused, and queued optimization candidates do not resume in this release train.

Package access remains a technical preview, without production-readiness,
competitive-superiority, broad SQL/DataFrame, object-store, lakehouse or Foundry
claims. Unsupported execution fails explicitly.

## Release closeout

The maintainer authorized another version bump/deployment train after the I/O

status was updated, the deployed site was verified and temporary artifacts were
