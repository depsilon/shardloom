# ShardLoom v0.6.0

Status: published technical preview through GitHub pre-release assets,
TestPyPI, PyPI and Homebrew. See the
[publication verification](v0.6.0-publication-verification.md) for exact source,
artifact identities and installation proof. Earlier releases remain immutable.
This minor technical-preview release packages the native Python API, wider typed
input, finite streaming composition and resource-accounting corrections accepted
since v0.5.1. SQL, Python, DataFrame declarations and the CLI continue to use the
shared Vortex-native engine. Unsupported execution fails explicitly.

## Migration: declare execution resources

Data inspection, preparation and execution now require explicit memory and
parallelism allocations. Configure both on a client, context or session, or
supply them to the terminal operation. Lazy declarations and inert capability
queries remain resource-free. There is no built-in allocation derived from host
memory or CPU count. For example, a caller may explicitly grant 256 MiB and two
execution lanes:

```python
import shardloom as sl
from shardloom import ExecutionResources

ctx = sl.context(resources=ExecutionResources(256 << 20, 2))
result = ctx.sql("SELECT COUNT(*) AS n FROM range(0, 100)").collect()
```

These values are illustrative caller choices. `memory_gb` uses GiB; the exact
byte form avoids rounding. A call may override one configured field while
inheriting the other, but cannot exceed an inherited administrator ceiling.
Environment configuration is loaded only through an explicit
`ExecutionResources.from_env()` call. Missing or invalid values fail with an
actionable configuration diagnostic. See the
[resource contract](../architecture/required-execution-resources-2026-10-10.md).
Applications relying on the previous implicit allocation must configure one
before upgrading. A query allocation is not a total-process RSS limit.

## Native Python plans and retained results

The optional `shardloom.native` API provides in-process sessions, typed relations
and expressions, plans, native results and incremental streams. Completed
results retain their native owners after the originating session closes and
can feed another native operation or an existing writer. Arrow stream import
and export are explicit interchange boundaries; Python row construction is a
separate requested endpoint. Complete native result collection does not inherit
the small JSON endpoint's row and payload limits.

`ShardLoomClient(transport="native", ...)` selects the shared Rust workflow
surface in process. The ordinary client continues to use its subprocess
transport. Existing high-level DataFrame expression builders retain their SQL
declarations; the typed relation API is explicit. No external query engine is
used for unsupported work. See the
[native API and ownership contract](../architecture/native-python-surface-2026-10-10.md)
and [complete acceptance](../benchmarks/native-python-surface-2026-10-11.md).

The release workflow includes the native module and bundled CLI in the Linux
x86_64 and macOS arm64 wheels, with the `cp310-abi3` contract. Linux publication
requires a successful `manylinux_2_39_x86_64` audit of both binaries. The audit
must preserve every runtime payload, then the exact wheel must pass isolated
loading, the complete native binding suite and uninstall verification.
The hosted interpreter checks cover Linux Python 3.10/3.13 and macOS Python 3.13.
Windows retains the CLI-backed Python package; its native extension is not
admitted. The clean Python source distribution does not bundle native binaries.
Actual artifact identities, platform tags and checks are recorded in the
[publication verification](v0.6.0-publication-verification.md).

## Wider input and streaming composition

Explicit Python schemas now admit exact-width signed and unsigned integers,
finite Float32/Float64, Boolean, UTF8, binary, Decimal128, Date32, timezone-free
microsecond timestamps, lists, fixed-size lists and ordered structs. Existing
scalar aliases and inference remain compatible; rich types require an explicit
schema. Values outside Python's calendar range remain exact epoch integers.
Top-level field metadata and cumulative retained batch metadata grow under the
shared allocation rather than a fixed total field or batch count. The row-frame
and small-result endpoint bounds still apply. See the
[typed input](../architecture/native-typed-input-2026-10-10.md) and
[input growth](../architecture/native-input-growth-2026-10-09.md) contracts.

Finite streaming input can combine multiple producers, repeated source
references and dynamic pivots through the admitted native operator families.
Each original producer is consumed once per execution. Declared repeated scans
retain admitted native replay state and may use explicit native spill; they do
not call the producer again. Independent sources require independent completion,
and late failure prevents final success or output publication. Compatibility
inputs normalize to Vortex through the same cancellable transaction and grant.
Native writer batching and demand-sized result reads preserve complete
write/reopen behavior under the accepted allocation. See the
[composition contract](../architecture/native-stream-input-composition-2026-10-13.md).

## Native ownership, recovery and execution work

Reviewed Zstd selection state and fixed-width child-decoder scratch are admitted
before allocation. Aggregate, predicate, export and nested-value helpers retain
the caller's execution context and propagate provider failures. Result owners
retain their credits independently of temporary decoder state. The correction
preserves native direct append, FoR fusion and sparse-frame avoidance. These are
finite allocation contracts; other provider trees, structural metadata,
compression/training and allocator overhead are not newly covered.

The release also retains accepted encoded transfers, native output statistics,
filtered-count selection and sparse text-frame work avoidance. Their reports
record the measured target workloads and rejected alternatives; there is no
general engine speedup claim. Full-domain timestamps use the admitted native
provider without converting execution into an external engine.

Controlled abandoned-spill cleanup now accepts caller cancellation. Actual
operator process-death tests cover cleanup and fresh restart for numeric sort,
single/compound-key counts and exact integer distinct counts, in addition to
the existing stateful families. Active or unknown owners remain protected.
This does not resume interrupted execution. See the
[operator recovery contract](../architecture/native-operator-recovery-2026-10-13.md).

## Acceptance and remaining scope

The [fresh October 14 UAT](../benchmarks/native-fresh-unpaced-uat-2026-10-14.md)
completed before the version change. It ingests all 99,997,497 rows into a fresh
Vortex artifact, passes all 129 predeclared query calls and all 18 modular
cohorts, including 1,408 comparisons and 704 native executions. Native ingest
takes 54.603468 seconds; all query process times sum to 194.125941 seconds;
the supervised ingest-plus-query workflow takes 331.624211 seconds. These are
unpaired source-build observations, not timings of the later published packages.
Future full-query UAT defaults to one call for each of the 43 queries; repeats
require an explicit override, and one pass has no hot-run statistic.

The [combined context acceptance](../benchmarks/native-admitted-context-2026-10-14.md)
records source gates, 80 direct binding tests, 757 public cases and 516 matched
query calls. No query repeats a declared cost breach in both starting orders.
Historical slower and interrupted observations remain preserved; this does not
establish a single cause for their timing differences.

Source acceptance, release packaging and published-channel installation are
separate evidence. The support label remains a local technical preview with
operational hardening in progress. Broader reader/codec ownership, compatibility
streaming destinations and fanout, platform coverage, further local workflows
and conditional optimizations remain with their existing owners. Internal Rust
crates remain unpublished. Production certification, distributed execution,
cloud/table transactions, full SQL/DataFrame parity and competitive superiority
are not claimed. Vortex remains native input and highest-fidelity output, with
no external execution fallback.
