## Native mechanism and boundary

The candidate implements an original, fixed 1,024-byte/8,192-bit necessary
byte-trigram signature through the existing Vortex zoned aggregate, layout,
statistics rewrite and scalar provider APIs. Its persisted identifier is
`shardloom.text_trigram.v1`, with explicit `shardloomtext` edition `2026.11.0`.
The pinned Vortex 0.93.0 exact/prefix lexical rules remain in place. No new
execution dependency, external residual evaluator or decode-to-Arrow execution
path is added.

Positive case-sensitive literal LIKE tests may reject a zone only when a
required byte trigram is absent. Windows never cross row boundaries. Unicode
and escaped literals retain exact byte semantics; surviving candidates receive
the ordinary exact predicate. Null, missing and saturated summaries are
distinct. More than half the bits set makes the optional summary inconclusive.
Short/empty, negated, folded, malformed or nonliteral patterns receive no new
summary exclusion. Those rules and thresholds were fixed before timing.

The explicit writer composition admits its bounded table, leaf references and
retained owners against the native memory pool before construction. Reader
registration is limited to the local/write/Unix feature boundary. The shared
planner unwraps Boolean identity comparisons only around the admitted
`StringContains` condition, allowing ordinary SQL and the other user surfaces
to reach the same provider. All candidate implementation, fixture and test
changes are preserved on the experimental branch and removed from the active
accepted source after the decline.
