# Multiway prototype representation admission

This clarifies the prospective `multiway-probe-817-v1` strategy before its first
build or execution. All eight frozen fixtures and quantitative gates are unchanged.

`ResidentMemorySource` is immutable, but can also retain completed native results,
encoded transfers and generated ranges. A memory-scan tag and integer logical
dtype alone do not prove that earlier key preparation cannot execute a deferred
provider. The finite prototype therefore admits only pure memory projections
whose projected fields are already host integer primitive arrays, with constant
validity or a host boolean validity bitmap, in an existing canonical struct.
It inspects representations without reading scalar values or allocating buffers.
Generated ranges, encoded/deferred fields and other payload types remain on the
ordinary strategy. This is a conservative representation boundary, not a new
input limitation or a claim of general encoded multiway execution.

The native payload owner and original integer widths remain shared. Reordering
key preparation cannot introduce a new arithmetic, parsing or deferred-provider
error for this admitted representation. Capacity denial and cancellation retain
the shared native owner and explicit failure contract. Broader representation
support would require its own error-order and provider evidence.
