# FSST with encoded predicate execution — R6.b

Status: bounded native admission screen, no retained runtime change.
This follows the R7 and R1.b drops under PERF-INTAKE / RFC 0044.

Pinned Vortex 0.85.0 supplies FSST training/compression, Flat/Chunked persistence,
and a LIKE kernel that evaluates supported constant case-sensitive patterns over
compressed symbols. ShardLoom already uses that kernel in its direct text helper;
public contains predicates can also lower into native LIKE scan pushdown.
The provider decision is `use_vortex_native_provider`. Existing public
`data_decoded=false` reporting describes the adapter's residual work and does not
prove which internal codec kernel ran. Do not use that flag as dispatch evidence.

First compare the retained source-text Zstd writer with encoded FSST for Title
and URL on the first 131,072 rows of source row groups 0, 113 and 225. Reuse the
bounded R1.b Parquet conversion and native write/reopen harness. Preserve the
current table/derived-dictionary handling; only the test's selected field writer
changes. Charge FSST training and compression separately before native writing.
Cap every in-memory artifact at 64 MiB, native credited memory at 512 MiB, and
stdout at 2 MiB. Provider buffers outside the pool remain explicit. The UAT
watchdog and unchanged input generations are required; no full-size artifact
is generated by this admission screen.

Reopen every artifact and compare every original UTF8 value and validity. On
persisted native blocks, evaluate the existing `google`, `Google` and `.google.`
contains patterns (including negation), compare exact Boolean selections with
an independent byte oracle, and separately record preparation, write and native
consumer timings. Call the FSST LIKE kernel explicitly for an encoded-kernel
witness; distinguish that witness from proof of dispatch through public scan.
Record scan pushdown and complete native count results where available. Neither
kernel microtimings nor these prefix scans constitute complete ClickBench calls.

Only a materially promising lifecycle advances to a production candidate and
public-route dispatch proof. Retention requires the existing storage, suite or
complete-query gate, full guarded ingest, exact native values/schema/statistics,
Full43 and independent renamed/null/Unicode/pattern/error/resource fixtures.
Include effects on nonpredicate consumers and charge training/persistence;
demonstrate reuse break-even if preparation grows. Otherwise preserve the evidence,
drop the tested variant and advance to R1.c. No new codec, dependency, fallback
engine, package release or public feature is introduced by the screen.
