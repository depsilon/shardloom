# Shared ownership and combined workflow acceptance

## Accepted local scope

The shared native incorporation and existing-depth combined workflow checks pass
local acceptance. The changes correct planning/application reports and worker
cancellation, preserve completed-result ownership, and exercise the existing
native operators through complete public workflows. The
[acceptance packet](../release/evidence/shared-native-incorporation-2026-11-18/README.md)
binds exact sources, commands, original failures, artifact identities and results.
Hosted review and required checks remain pending; this is not merge, publication,
item-19/item-20 completion or competitive acceptance.

The [incorporation contract](native-shared-capability-incorporation-2026-11-17.md)
classifies new performance mechanisms as `v1_candidate_pending_feasibility`.
Its bounded numeric and UTF8 worker screens admit **no new finite PulseWeave
control**. Existing `AdaptiveWorkSizer`, queue admission and writer controls
remain authoritative. Actual finite feedback is deferred pending new material
owner evidence; it is not marked implemented. This explicit no-change decision
does not leave an unselected optional performance mechanism blocking the next
functional item. The [phase plan](phased-execution-plan.md#current-execution)
continues with Chrysalis, then Resonance, under their separate design and gates.

## Lifecycle and control result

The [required cancellation correction](native-shared-capability-incorporation-2026-11-17.md#completed-result-cancellation-correction)
checks cancellation before and after completed-result merge, cancels sibling
work on failure or unwind and preserves the original provider/consumer error.
Eight non-spill worker families use an operation-aware stage token; explicit
weighted-count spill retains its existing separate domain. Reservations and
window permits survive completion until consumption and final owner release.

The [string delivery controls](../release/evidence/shared-native-string-delivery-2026-11-17/README.md)
exercise actual partition workers through full native output, detached slices,
consumer failure, cancellation, memory refusal, panic, retry and final refund.
A once-only worker producer supplies existing native replay and Vortex/JSONL
fanout, with complete readback. Panic retains the existing poisoned-session
contract; recovery uses a fresh session. No poison clearing was added.

Optional worker-wait observation reserves its metadata before worker startup and
measures only actual condition waits. Ordinary construction keeps it disabled.
The numeric screen executes 18 declarations once in each observation mode; the
UTF8 screen executes 15 declarations once in each mode. Full queues do not block
producers in these observations. More UTF8 partition-lock waiting coexists with
lower engine time at higher parallelism, so overlapping waits cannot be treated
as attainable savings from reducing concurrency. Neither screen establishes a
speedup, causal attribution or a stable instrumentation overhead bound.

No new policy, repeated benchmark campaign, removed ingest/COUNT experiment,
full10k or Full43 is introduced. Unmeasured vector/preparation opportunities
remain unobserved. Pure FlowInventory, ScarcityLedger, EndoPulse and PulseWeave
reports retain their planning role and unavailable execution observations.

## Combined user workflows

The mixed Float16 lifecycle fixture now carries document and nullable portfolio
IDs, ordinary nested attributes, dense vectors, embedding-space identity, fixed
and variable tensors, and distinct absent/empty/nonempty binary values. It retains
nonzero slices, component/parent nulls, signed zeros, NaN payloads, infinities and
subnormal bits. SQL and DataFrame each filter, duplicate-join, reorder,
force native spill and write Vortex; DataFrame streaming and early retained
batches are checked separately. The producer context closes before a separate
process reopens both outputs. Full values, field/child nullability, tensor and
embedding metadata, and retained results are compared with the original fixture.

The five-interface control writes through CLI SQL, Python SQL, typed relations,
DataFrame and embedded workflows. Source removal and client closure precede
separate-process reopen. Independent IPC readback covers all values. Parquet is
checked through the native reader and an independent reader; the pre-existing
PyArrow fixed-list/null-parent limitation remains explicit, with complete native
readback and independent present-parent controls. This is not full independent
Parquet acceptance for the affected null-parent representation.

Four new compact analytical workflows use independent expectations and complete
SQL/DataFrame collection, bounded streaming, Vortex/IPC writes, input removal,
fresh-context reopen and independent IPC readback:

- Per-fund statistics include null keys, all-null measures and singleton groups.
- Entity/currency as-of valuation includes duplicate quote times, missing matches,
  null keys/times and retained nested payloads.
- Timezone-aware daily reporting distinguishes 23-, 24- and 25-hour local days,
  including both autumn clock-fold instants and nullable measures.
- Parameterized multi-CTE composition uses materialization, nested payloads and
  two independent parameter bindings.

The existing custom batch-transform/join/aggregate workflow now adds independent
Parquet and IPC full-value/schema readback. Existing callback effect, failure,
cancellation and publication controls run in the same installed suite.

The sixth analytical workflow, safe remote dataset refresh, remains explicitly
deferred to its [existing I/O/Foundry owner](native-universal-io-implementation-2026-10-31.md).
Local output success is not substituted for remote deployment/readback.
Resource-admitted deep traversal resumes after Foundry; the public depth limit
and the remaining complete deep lifecycle are unchanged. These limitations keep
items 19/20 and their independent competitive obligations open.
