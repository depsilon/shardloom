## Mechanism and declared coverage

The shared prepared UTF8 evaluator applies lower, upper, trim, character length,
byte length and literal regex to referenced dictionary values, then retains a
native Vortex dictionary for existing consumers. It copies original-width codes
into independent credited ownership. Complete-domain UTF8 validation remains
before execution; unused valid values avoid text kernels, while invalid unused
values still fail. Null codes, null values, Unicode collisions, changed domains,
slices and exact cross-dictionary equality retain their typed semantics.

The 4,150 original declarations are selected from the existing inventory in
manifest order, without looking at timings. The 1,380 added declarations cover
two sizes, six profiles, 23 forms and all five public surfaces: CLI SQL, embedded
workflow, Python SQL, DataFrame and typed relation. Nonempty public fixtures have
71 rows; work fixtures have 12,291 rows in three explicit native chunks. Empty
fixtures have zero rows. Dictionary, sparse, all-null, unique and flat profiles
exercise real native representation and ordinary-path controls. Sparse inputs
retain unused long values and distinct dictionaries across chunks. Independent
Python references enumerate every expected cell and schema.

All 630 declared dictionary-activation cases and 210 work-reduction witnesses
pass. The work witnesses compare actual candidate text-kernel invocations with
their logical expression rows. The baseline has no equivalent work counter;
these are not measured before/after kernel counts. Retained codes are still
inspected and copied. The result proves neither zero-decode execution, physical
device-byte savings nor process RSS. Union-before-transform, selected-input,
flat, unique and empty controls keep their admitted ordinary behavior.

The implementation uses the pinned Vortex 0.93.0 `DictArray` and existing native
allocator, expression, key, selection and result owners. It introduces no
execution dependency or external-engine fallback. Complete public outputs,
write/reopen behavior, source changes, cancellation/retry and retained-child
ownership are covered by the public and installed-package proof.
