## API migration

Version 0.7.0 adds one context lifecycle and one collected `Result` contract.
The [migration reference](https://github.com/depsilon/shardloom/blob/main/docs/reference/python-api-migration.md)
describes the deliberate changes and compatibility window.

| Task | Current API |
| --- | --- |
| Own execution resources and lifetime | `with sl.context(...) as ctx:` |
| Inspect the selected installation backend | `ctx.transport` |
| Collect complete data and inspect values | `result.schema`, `result.to_rows()`, `result.details` |
| Reuse completed native data | `ctx.from_result(result)` |
| Stop current work or revoke future work | `ctx.cancel()`, `ctx.close()` |
| Discover inspection or maintainer types | `sl.diagnostics`, `sl.testing` |

Linux/macOS native installations select in-process execution by default;
Windows and explicit CLI configurations select process isolation. Choose
`transport="subprocess"` explicitly when needed. A failure never changes the
selected backend. Memory and parallelism remain explicit caller choices.

## Included 0.7.0 capabilities

Version 0.7.0 includes finite streaming composition and bounded native resource
accounting. Streaming covers the admitted compatibility destinations, set and
unary operations, and static/dynamic subquery composition; late producer errors,
cancellation, and invalid generations prevent successful completion or final
publication. Explicit spill permission covers the listed relational membership
and sampling workloads. These are finite operator contracts: they do not make all
state spillable, establish a total-process memory ceiling, promise multi-file
atomic publication, or resume interrupted queries. Native structural storage
admission covers six classes: child caches/classification, cumulative row offsets,
reader metadata vectors, segment specifications, file statistics tables, and user
metadata names/locators. See the [v0.7.0 release notes](https://github.com/depsilon/shardloom/blob/main/docs/release/v0.7.0-release-notes.md)
and its linked acceptance records for exact workloads and limits. Future source
work is separate; pin source commits for reproducibility.
