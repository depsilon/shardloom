## Published package and source

The lifecycle and `Result` API described here is included in
[v1.0.0](https://github.com/depsilon/shardloom/blob/main/docs/release/v1.0.0-release-notes.md). Published package availability
is tracked in the [selected-channel package readiness matrix](https://github.com/depsilon/shardloom/blob/main/docs/release/package-channel-readiness-matrix.md).
For reproducible future source work, pin source commits and follow
[source installation](https://github.com/depsilon/shardloom/blob/main/docs/getting-started/source-checkout-install.md).

## Current source capabilities

The current checkout is the [1.1.0 source milestone](https://github.com/depsilon/shardloom/blob/main/docs/release/v1.1.0-release-notes.md).
Published packages remain at 1.0.0. Build matching Python and CLI components
from one pinned revision with `release-user-surfaces`, and inspect that build's
capabilities before using a format or operator.

| Task | Current source support | Boundary to keep explicit |
| --- | --- | --- |
| Compose SQL and DataFrames | Named scalar parameters, query-local relations, nested CTE scopes, admitted recursive queries and explicit CTE materialization. | Parameters are values, not SQL text; recursion has declared limits. See [connected programming](https://github.com/depsilon/shardloom/blob/main/docs/reference/connected-programming.md). |
| Analyze richer values | Extended numeric/aggregate and temporal/time-series operations share typed native execution. | Each operation has type, overflow, NULL and ordering rules; file adapters retain their own schema profiles. |
| Read ordinary local sources | Shared direct readers for admitted text, columnar and structured files. | Durable Vortex preparation is explicit. Remote connectors are separate work. See [data lifecycle](/field-guide/execution-routes). |
| Read table state | Local Iceberg v1/v2, admitted Delta profiles and Hudi Copy-on-Write v8/v9. | Explicit format and snapshot rules; no catalog access or table writes. See [local snapshots](/field-guide/local-tables). |
| Deliver multiple outputs | One supported `fanout` action computes once and writes its requested destinations. | Final publication is not a multi-file atomic transaction. See [writers](/field-guide/runtime-and-io#write-multiple-results-in-current-source). |
| Adapt work to available capacity | Source batches, conversion windows, queues, output gathers and native spill blocks use admitted shared headroom. | Physical and semantic minimums remain; reservations are not a total-process memory cap. See [resources](/field-guide/resources#adaptive-work-in-current-source). |

The [five-interface example](https://github.com/depsilon/shardloom/blob/main/examples/source-interfaces/run.py)
creates a small local source, checks complete answers through DataFrame, Python
SQL, typed native, embedded workflow and CLI SQL, then reopens two outputs and
an explicitly prepared Vortex input. Run it with a matching native installation
and CLI from the same source revision:

```sh
python examples/source-interfaces/run.py --binary /absolute/path/to/shardloom
```

It prints the two rows `{"id": 2}` and `{"id": 3}` and a passing status, then
removes its temporary files. Its resource settings are examples, not workload
sizing recommendations. The [source acceptance matrix](https://github.com/depsilon/shardloom/blob/main/docs/release/public-status-matrix.md#current-source-additions-after-100)
links the detailed implementation evidence and remaining limits.

## API migration

Version 0.7.0 introduced one context lifecycle and one collected `Result` contract.
The [migration reference](https://github.com/depsilon/shardloom/blob/main/docs/reference/python-api-migration.md)
describes the deliberate changes and compatibility window.

| Task | Current API |
| --- | --- |
| Own execution resources and lifetime | `with sl.context(...) as ctx:` |
| Inspect the selected installation backend | `ctx.transport` |
| Collect complete data and inspect values | `result.schema`, `result.to_rows()`, `result.details` |
| Reuse completed native data | `ctx.from_result(result)` |
| Stop current work or revoke future work | `ctx.cancel()`, `ctx.close()` |
| Discover inspection or maintainer types | `sl.diagnostics`, `sl.testing` |

Linux/macOS native installations select in-process execution by default;
Windows and explicit CLI configurations select process isolation. Choose
`transport="subprocess"` explicitly when needed. A failure never changes the
selected backend. Memory and parallelism remain explicit caller choices.

## Reuse completed data

This example for the published 1.0.0 API returns the same two rows after the original
context closes. Native admission retains ShardLoom-owned data without an Arrow
or Python-row export. A process-backed context uses typed payload conversion.

<Code code={developmentExample} lang="python" title="context-result.py" />

```text
({'id': 1}, {'id': 3})
```

`to_rows()` allocates Python objects explicitly. Keep large delivery in batches
or a writer. See the [v1.0.0 release notes](https://github.com/depsilon/shardloom/blob/main/docs/release/v1.0.0-release-notes.md)
for the included API and its compatibility details.

## Included 1.0.0 capabilities

Version 1.0.0 includes finite streaming composition and bounded native resource
accounting. Streaming covers the admitted compatibility destinations, set and
unary operations, and static/dynamic subquery composition; late producer errors,
cancellation, and invalid generations prevent successful completion or final
publication. Explicit spill permission covers the listed relational membership
and sampling workloads. These are finite operator contracts: they do not make all
state spillable, establish a total-process memory ceiling, promise multi-file
atomic publication, or resume interrupted queries. Native structural storage
admission covers six classes: child caches/classification, cumulative row offsets,
reader metadata vectors, segment specifications, file statistics tables, and user
metadata names/locators. See the [v1.0.0 release notes](https://github.com/depsilon/shardloom/blob/main/docs/release/v1.0.0-release-notes.md)
and its linked acceptance records for exact workloads and limits. Future source
work is separate; pin source commits for reproducibility.
