## Direct native Python

`shardloom.native` exposes `Session`, `Source`, typed `Expression` and `Relation`,
prepared `Plan`, retained `Result`, and stream owners. It is useful when embedding
typed native declarations. Ordinary Python applications can stay with
`sl.context(...)` and select native transport.

Declare explicit `ExecutionResources` when constructing a native session.
Build plans without executing producers; execute with collect, batch delivery,
or a writer. A completed result retains its native owner after session close.
`row_export()` explicitly requests Python objects; Arrow stream export is an
optional conversion boundary and may allocate. Foreign columnar admission may
copy into the receiving grant.

See the [native module reference](https://github.com/depsilon/shardloom/blob/v0.7.0/python/src/shardloom/native.py)
and [source-build instructions](https://github.com/depsilon/shardloom/blob/main/docs/getting-started/source-checkout-install.md#optional-native-python-binding).
The [typed result contract](https://github.com/depsilon/shardloom/blob/v0.7.0/docs/reference/resident-native-results.md)
defines ownership and export semantics.

## Rust integration

Workspace crates are unpublished. Build from a checked-out source revision and
use the repository's crate/API documentation; there is no supported crates.io
installation command for these internal crates. Vortex provider dependencies
remain isolated in the adapter boundary, and typed embedding uses ShardLoom's
resource, planner, provider and certificate contracts.

Future public Rust packaging has an existing release-engineering owner. It does
not authorize publishing the current workspace or using external-engine fallback.
