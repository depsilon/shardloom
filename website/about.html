About

One engine. Familiar interfaces.

ShardLoom is a unified data processing engine for reading, transforming, querying, and writing data. Use SQL or DataFrames in Python, run queries from the command line, or embed the engine in an application. The published technical preview supports specific local workflows today.

Differentiators

Keep useful structure through the whole pipeline.

The engine avoids unnecessary reads, decoding, copies, and intermediate data. Support depends on the operation and data types; the reading and writing guide explains those limits.

Work avoidance

Use what the data already knows.

Exact metadata can answer supported queries before row reads. Statistics prune segments; encoded kernels use dictionary codes, values, and repetition counts. Supported top-K queries fetch result values after selecting the needed rows.

Exact aggregation

Exploit repetition without approximating the answer.

Weighted counts, fused SUM/AVG work, complete key partitions, and delayed measures preserve exact DISTINCT and grouping equality. Retained strings, compact counts, and shared intermediate state reduce repeated construction for supported operations.

Preparation

Reuse loaded data while it remains valid.

Supported input files can reuse data previously loaded into Vortex. Source, schema, and file identity checks reject detected changes. An existing Vortex source preserves its layout.

Query preparation

Retain setup, renew query state.

Prepared queries retain eligible source handles and query setup. Python contexts reuse a local worker to avoid starting another process for each call. Each execution computes a fresh result.

Results

Carry results into their next consumer.

Supported results retain engine-owned columnar data and memory reservations. Eligible Rust operations can consume them directly, and shared writers export flat results without rerunning the query or reconstructing them from JSON.

Local I/O

Choose a format at the boundary.

Readers and writers support Vortex, Parquet, Arrow IPC, Avro, ORC, CSV, JSON, and JSONL within documented type and operation limits. Vortex retains the most information; other formats report differences in types and metadata.

Resources

Make pressure and ownership visible.

Memory and parallelism settings govern supported work. Reservations, bounded queues, cancellation cleanup, and selected spill operations make resource use inspectable. Memory accounting identifies its scope; it is not a limit on all process memory.

One engine

Know which engine executed the work.

ShardLoom executes supported work and rejects unsupported requests with deterministic diagnostics. It does not delegate execution to another query engine. Structured reports retain the exact execution and policy details.

Available today

A technical preview you can install.

GitHub pre-release, PyPI, TestPyPI, and Homebrew publication is verified for 1.0.0. The support matrix and guide document available operations, types, and platform requirements.

The breadth and scale plan completes whole read, transform, and write workflows: native result streaming, broader operators and types, shared resource accounting, spill, and adapters. These extend the same engine. General computed-result exports remain bounded today.

Timing

Measure execution and verification separately.

Use ShardLoom as the system name, then disclose the version, hardware, interface, loading procedure, stored format, resource settings, cache conditions, and measured work.

Engine execution

Measure the query work.

Routine query comparisons use engine execution time. A 43-query ClickBench workload total includes one execution of each query, with the cache conditions stated.

Loading and preparation

Disclose how the data was made ready.

Record source and stored formats, loading steps, storage size, and what setup was reused. Preparation is separate from query execution.

Result validation

Check the answer separately.

Verify values, schemas, and written outputs. Keep validation and report generation separate from engine execution, and retain the full measurement record.
