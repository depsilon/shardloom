About

Less repeated work. One native engine.

ShardLoom is being built for general-purpose data processing through one Vortex-native pipeline. Python, SQL, DataFrame-style calls, and the CLI describe the work; adapters connect sources and destinations. The published technical preview supports specific local workflows today.

Differentiators

Keep useful structure through the whole pipeline.

The engine avoids reads, decoding, copies, and materialization where the admitted operation allows it. These capabilities have specific type and operator limits; the runtime and I/O guide makes those limits explicit.

Work avoidance

Use what the data already knows.

Exact metadata can answer supported queries before row reads. Statistics prune segments; encoded kernels use dictionary codes, values, and repetition counts. Top-K routes defer payload gathering until selection.

Exact aggregation

Exploit repetition without approximating the answer.

Weighted counts, fused SUM/AVG work, complete key partitions, and delayed measures preserve exact DISTINCT and grouping equality. Retained string owners, compact count state, and shared partials avoid repeated construction on admitted routes.

Preparation

Reuse an artifact only while its identity holds.

Unchanged compatibility inputs can reuse schema-bound Vortex preparation. Source and artifact generation checks reject detected changes. Native Vortex preparation preserves the input layout.

Resident execution

Retain setup, renew query state.

Prepared sessions retain source handles and lowering for supported families. Python contexts reuse a local worker to avoid per-call process startup; each query gets fresh execution state.

Native ownership

Carry results into their next consumer.

Supported results own Vortex arrays and memory credits. Bounded Rust composition can consume them directly; flat result exports reach shared writers without rerunning the query or reparsing serialized JSON.

Local I/O

Choose a format at the boundary.

Vortex, Parquet, Arrow IPC, Avro, ORC, CSV, JSON, and JSONL use explicit adapters and writers. Vortex remains the highest-fidelity persistence target; compatibility export exposes type and metadata limits.

Resources

Make pressure and ownership visible.

Bounded queues, reservations, cancellation cleanup, and selected native spill routes govern admitted work. Metadata-only aggregates avoid payload and worker admission; native file operations drain admitted I/O and readers before completion. PulseWeave and typed capillary work units expose control decisions.

No fallback

Know which engine executed the work.

Structured route evidence exposes fallback_attempted=false and external_engine_invoked=false. Unsupported work returns a deterministic diagnostic instead of silently delegating to another query engine.

Available today

A technical preview you can install.

GitHub pre-release, PyPI, TestPyPI, and Homebrew publication is verified for 0.3.3. Package availability does not imply production support or broad SQL/DataFrame parity.

The breadth and scale plan completes whole read, transform, and write workflows: native result streaming, broader operators and types, shared resource accounting, spill, and adapters. These extend the same pipeline. General computed-result exports remain bounded today.

Timing

Measure execution and verification separately.

Benchmark labels identify which work a timer includes. They describe measurement boundaries within the same pipeline.

hot_runtime

Runtime measurement

Default performance view. Result-sink replay and human evidence rendering are excluded unless the route formula explicitly includes them.

full_replay_proof

Machine replay proof

Shows runtime plus replay or sink proof work when that row declares the cost as part of the proof surface.

publication_proof

Publication verification

Includes result-sink checks and human evidence rendering when publication requires them. The measurement accounts for this additional verification work.
