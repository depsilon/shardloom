Installation and artifact verification · Release source

The example selects transport="native" on Linux or macOS. On the Windows package, use transport="subprocess". This changes process isolation, not the query engine. The Windows wheel has build and artifact inspection evidence; it does not have the Linux/macOS native runtime coverage. The source distribution contains no compiled engine; use the source build instructions if no wheel matches your platform. PyPy and other CPU/OS combinations are not covered by these wheel tags.

Read and collect

Section titled “Read and collect”

Save this as quickstart.py and run python quickstart.py. It creates the CSV in a new temporary directory, so it needs no pre-existing file or working directory. The 256 MiB and two lanes are small example allocations selected by the caller, not defaults or machine sizing advice.

Expected values:

read_csv, filter, and sort declare the plan. collect(check=True) executes it and raises a typed error on execution failure. Accessing python_objects explicitly allocates Python values from the completed result. This example is small; use batches or a writer for larger output.

Inspect execution details

result.result_schema describes the delivered columns. result.envelope contains the structured execution report; result.fallback_attempted and result.external_engine_invoked are false. Inspection does not rerun the query.

Get help

Section titled “Get help”

For installation, resource, or unsupported-operation errors, use troubleshooting. Check version-specific capabilities and known issues before expanding this example. Unsupported work raises a diagnostic; it is never delegated to another query engine.

Source builds and unreleased API changes have their own development and migration page.
