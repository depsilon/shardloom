Runtime limits

Section titled “Runtime limits”

Availability below is scoped to v1.0.0. The platform table specifies the available backends.

CSV, JSON, JSONL/NDJSON, Vortex, Parquet, Arrow IPC/Feather, Avro and ORC		Published CLI or Python wheel; source builds need the matching format featuresLocal paths only. Reader options and representable types depend on the format; remote catalogs and transactions are separate work.

Admitted computed result schemas		Published Python wheelSmall computed-result collection is limited to 65,536 rows and 8 MiB. Use batches or a writer for larger admitted results. Python object conversion allocates separately.
Iterate result batches
Admitted finite results and explicitly typed finite producers		Linux or macOS Python wheel; native columnar ownership requires a native wheelFull drain and final success establish completion. Process batch pipes require POSIX; Windows users should use collection or a writer. Process frames contain at most 2,048 rows and 8 MiB. A yielded batch does not certify later input.
Write local results
Vortex, CSV, JSON, JSONL, Parquet, Arrow IPC, Avro and ORC		Published CLI or Python wheel with the matching writerUse a new destination. CSV translates nested values to JSON text; ORC rejects nested output. Individual writer fidelity and publication rules apply; multi-file atomic publication is not promised.

Exact supported operations still depend on schema and options. Capability or plan inspection can reject a request before execution; a successful smoke command is not evidence that an unrelated workload is implemented.

Known issues

Section titled “Known issues”
Situation What to do
No wheel matches the OS, architecture or Python ABI Use a listed environment or follow the source-build reference. Do not rename a wheel to bypass its platform tag.
Computed result exceeds collection limits Consume supported batches or write output; requesting a Python tuple does not enable unbounded collection.
A process input/result crosses a Python boundary Expect explicit serialization and bounded protocol frames; it is not zero-copy.
Python batch iteration on Windows Process batch pipes currently require POSIX. Use bounded collection or a writer; Windows batch delivery remains development work.
Memory remains live after close Retained results and consumer objects keep their own owners. Release those references when no longer needed.
A query needs spill Supply an explicit supported spill policy. A replay/output spill policy does not enable spill for every operator.

External systems

Section titled “External systems”

Local files, local Vortex manifests and partitions, and admitted table-file reads are the executable data boundaries covered here. Remote writes, catalog transactions, production object-store services, REST/Flight services and Foundry integration remain design and roadmap work. Arbitrary UDFs, Python callbacks and network/API/model effects need their own explicit admission; they do not run during capability inspection.

Release and readiness

Section titled “Release and readiness”

The package is available as a technical preview. Operational hardening remains in progress: a query allocation is not a whole-process RSS ceiling, and reader/codec scratch and failure coverage have remaining work. The local-engine acceptance criteria define the support commitment separately from feature availability.

Correctness coverage and performance evidence are separate facts. Available execution does not by itself establish a comparative performance claim.

Extending breadth and volume

Section titled “Extending breadth and volume”

Development adds supported operations and types to the same ShardLoom engine. The development and migration page describes the published API and how to distinguish later source work. Immutable published packages retain their release-time behavior.

Failure behavior

Section titled “Failure behavior”

Unsupported work produces a deterministic diagnostic. ShardLoom never executes it through Spark, DataFusion, DuckDB, Polars, or another fallback engine. Use troubleshooting to inspect the structured error.
